# 模型倍率适用分组

“自动配置 → 模型计价”中，每条规则独立选择适用分组。勾选使用稳定的分组 ID，与初始化账号分组、并发升级分组独立。清空选择即适用于全部分组，包括无分组请求；限定范围的规则不会匹配无分组/未知分组。

匹配时先过滤不适用本次计费分组的规则，再按模型完整名称优先、最长前缀次之选择一条。模型名仍全局唯一，不支持同模型按分组配置多条重复规则。模型名和原倍率值不会因增添分组选择而改变。

分组来自本次计费 API Key 的 `GroupID`，与 usage log 的分组一致。仅更换上游账号不改变范围；现有 handler 真正切换计费分组时，使用传入计费的替代 API Key。不会使用上游账号所属的全部分组或用户的全部授权分组。

## API 与旧客户端

`model_billing.rules[].group_ids` 为正的 JavaScript 安全整数数组，重复 ID 按首次出现去重；非法类型、小数、非正值和超过安全整数的 ID 被拒绝。新选择按现有管理员组仓库逐 ID 确认为启用分组，不按模型名称限制平台。已保存后删除/停用的分组 ID 仍保留，允许保存其他配置；页面显示不可用 ID，可显式取消选择。分组分页全部成功后才开放范围编辑，失败时保留原范围并提供重试。

首次读取旧配置时，省略、`null`、`[]` 均表示全部分组。管理员保存遵循现有“先读当前配置再绑定 JSON”的兼容契约：

- 省略整个 `model_billing` 或 `rules`：保留原值。
- 提交规则但省略 `group_ids`：按规范化模型名（去空白、不区分大小写）继承该规则的已有范围，重排不影响；若当前没有受限规则，新模型默认为全部分组；已有受限规则时，新模型必须显式提供 `group_ids`，避免旧客户端重命名规则意外扩大范围。
- 显式 `group_ids: []` 或 `null`：清空范围，适用于全部分组。新页面始终发送数组。
- 显式删除规则仍会删除该规则。旧客户端在存在受限规则时改模型名或添加新模型会因缺少显式范围而被拒绝，需使用新版页面或显式提交范围。

保存不刷新原有计费缓存策略，最多约 15 秒生效；一次计费内的候选模型、响应模型和 Free Fast 重算共享同一配置快照。此字段仅决定现有 token 附加倍率是否适用，不改基础价、上游/账号成本、分组/账号/高峰倍率、按次价格、搜索附加费或扣费幂等协议。不涉及数据库迁移或历史用量重算。

旧二进制不认识范围字段，会按旧全局倍率收费。若维护者回退版本，应先停用受限模型倍率或明确调整配置；回退本身不能保留分组范围。本功能不对历史用量补扣。
