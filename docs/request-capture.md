# 请求采集

用于管理员排查客户端输入, 实际上游请求, 上游响应和客户端最终响应之间的差异. 默认关闭, 仅保留已确认出错的请求或 WebSocket 轮次, 不自动重放请求.

## 使用

1. 在系统设置 > 功能开关 > 请求采集启用功能, 设置文件总配额与保留天数. 默认 1024 MiB 和 7 天; 配额为正整数 MiB, 保留期为 1-30 天. 保存即时生效, 无需修改 Compose 或环境变量.
2. 打开管理员侧边栏请求采集, 搜索一个用户, 上游账户或分组, 设置 1-1440 整数分钟的采集时长.
3. 默认只记录媒体类型, 长度及可计算的摘要. 仅在必要时勾选保存媒体正文; 不会下载外部 URL.
4. 按 Request ID 筛选已收尾的错误记录, 查看四段文本, 工具内容, 流式事件及重试编号. 正文按最多 256 KiB 分段读取, 不作为 HTML 渲染.
5. 停止任务并等待收尾后, 导出单条记录或整个任务. 流式 tar.gz 包含实例标识, task.json, record.json 与阶段文件. 网页保存使用 File System Access API, 需要支持该接口的安全上下文浏览器, 例如 HTTPS 下的 Chrome/Edge. 管理员也可以使用已鉴权的导出 API 流式下载.
6. 排障完成后删除任务, 或等待保留期自动清理. 关闭总开关立即停采, 已确认错误的文件继续按任务结束时间及当前保留天数清理, 未确认错误的临时内容删除. 重启将未结束任务标记为 interrupted, 不自动恢复.

## 仅保留错误

- 待判定请求在受限预算内临时落盘, 不写入可查询的请求索引, 不允许查看, 预览或导出. 这不等同于正常请求从未经过磁盘.
- HTTP 请求完成后立即触发异步收尾. 没有确认错误时删除临时正文, 释放配额, 不保留请求索引. 删除由有界写入队列按顺序执行, 不等待定时保留清理, 也不阻塞业务响应.
- WebSocket 每轮收到客户端终态帧后独立收尾, 正常轮次立即排队删除, 无需等待断连. 错误轮次不会隐式保留同连接其他正常轮次. 若客户端在错误请求中显式携带历史消息, 这些消息仍属于该错误请求正文.
- 错误依据为 HTTP 4xx/5xx, 明确的 JSON/SSE/WS 错误或实际转发读写失败. 重试中曾发生错误但最终成功的请求仍保留该请求的采集记录, 用于排查换号和协议转换. null/false/空字符串 error 字段不视为错误.
- 采集队列满, 预算不足, 写盘失败或不完整标志本身不是业务错误. 没有确认错误的停采, 关闭, 到期, 取消或中断数据均删除. 已确认错误的部分记录可保留并标注不完整原因.
- 启动时清除未提交错误索引的孤立文件, 未完成索引及旧版正常记录, 重新校准占用和统计. 清理失败时停止采集并显示存储异常; 无索引数据仍不可查看, 修复存储后重启重试清理.
- 页面及后端强制只读取已收尾的错误记录, 不能通过 errors_only=false 绕过. 任务的请求数, 不完整数及文件大小只计保留的错误记录; 实例磁盘占用包含尚待判定的临时文件. 已丢弃的不完整采集计入跳过数量.
- 文件删除不等于存储介质安全擦除. 外部备份, 文件系统快照及管理员已导出的副本不在自动删除范围内. 错误正文仍有隐私风险, 应最小化采集范围与保留期.

## 范围与保护

- 用户按认证用户 ID, 分组按入口 API Key 分组匹配, 额外记录最终路由分组.
- 账户按实际选择的上游账户匹配. 客户端输入与最终输出可保留, 其他账户仅保留重试摘要, 上游正文仅保留目标账户的尝试.
- 采集任务启动后进入网关的 HTTP 请求及 OpenAI WebSocket 连接. WS 首帧和后续轮次带轮次与尝试序号, 支持现有 WS/HTTP 桥接. 已在传输的请求或已建立的 WS 连接不追加采集, 应重新建立连接后复现.
- 重叠任务分别保存, 执行各自媒体策略, 所有副本占用同一文件配额.
- 覆盖 JSON, SSE 和 WebSocket JSON. image/audio/video/octet-stream 在媒体正文开关打开后按 base64 保存; 其他未知格式, 包括 multipart, 只保留长度及摘要并显式标记省略. JSON 媒体摘要针对原始 JSON 字符串编码字节, 不能当作解码文件摘要.
- 文件位于 DATA_DIR/request-captures, DATA_DIR 未设时使用 ./data. 目录权限 0700, 文件 0600. 数据库仅保存元数据, 正文不进入 Ops 日志或管理审计.
- 认证头采用白名单排除, 结构化认证字段及 URL 凭据和敏感查询参数在写盘前脱敏. 无法安全解析的片段省略并标记. 普通对话, 工具字符串或用户文件仍可能包含秘密, 采集内容必须作为敏感业务数据管理.
- API, 页面路由及菜单同时检查管理员身份和总开关. 创建, 停止, 删除, 正文读取, 导出与设置变化接入既有管理审计. 不提供公开文件地址.
- 本版为单实例本地磁盘, 不支持跨节点采集. 备份需同时处理数据库元数据和采集目录.

## 资源与失败行为

| 项目 | 限制 |
| --- | --- |
| 运行任务 | 16 |
| 并发采集会话 | 256 |
| 采集缓冲预留预算 | 64 MiB |
| 单条记录 | 128 MiB |
| 单条记录片段 | 512 |
| 尝试摘要 | 256 |
| 异步写入队列 | 1024 个有界分块 |
| 同时导出 | 2 |

- 转发路径不等待磁盘. 请求复制, 未匹配账户的临时输入, 队列分块和过滤状态使用预算准入. 单个写入器在追加文件前预占配额, 重叠任务也无法越过管理员配置上限. 导出不在内存聚合整包.
- 达到配额停止全部任务, 仅保留已确认错误的文件, 未确认错误的数据收尾删除. 降低配额不删除历史. 配额是管理员配置的保留上限, 不是物理磁盘容量或剩余空间百分比.
- 写盘失败, 索引失败, 队列满, 缓冲不足和单记录超限通过不完整错误记录或跳过计数体现, 不替换业务响应或关闭业务连接. 存储故障停止全部采集, 修复后重启并重新创建任务.
- 容量不足记录跳过计数. 无法安全归属的重叠 WS 轮次停止该连接的采集; 错误诊断事件解析上限 16 KiB, 超大或异常内容无法确认错误时不保留, 计入跳过. 未取得短时内部锁时累计实例准入跳过计数. 必须结合跳过与不完整数量判断材料是否齐全.
- 64 MiB 是采集缓冲预算, 不是进程 RSS/Go 堆的硬上限. 业务, GC, 数据库驱动, 导出等仍消耗内存. 大媒体或大量重叠任务会触发截断, 不能承诺任意 200 用户流量都完整采集.

## 验证

新增测试覆盖设置验证与字段遗漏保留, 默认隐藏与并发路由加载, 媒体默认关闭, 文本分页, 认证流式导出, 跨字节边界脱敏, 转义 URL, 异常 JSON/SSE, HTTP 四段对照, WS 多轮与换号, 重叠任务独立停止, 配额, 删除竞争, 写盘失败, 重启, 清理和 PostgreSQL 元数据存储.

复现命令:

    cd backend
    go test -race ./internal/requestcapture ./internal/server/middleware
    go test -tags=integration ./internal/repository -run TestRequestCaptureSQLLifecycle
    CAPTURE_LOAD_TEST=1 go test ./internal/requestcapture -run TestCapture200LongStreams -count=1 -v

2026-09-25 在 macOS arm64 的合成负载: 200 个并发采集会话, 100 个正常完成, 100 个 HTTP 502 错误. 每个包含 32 KiB 媒体输入, 约 10 秒长流, 上下游各 200 个 SSE 事件. 正常记录全部删除, 仅保留 100 条错误记录, 0 条不完整; 采集缓冲峰值 47,150,584 字节 (约 45.0 MiB), 保留文件 9,185,600 字节 (约 8.8 MiB). 采样 Go heap 从 698,040 字节升至峰值 41,052,008 字节, GC 后 825,432 字节. 文件描述符采样为 5/5/5 (开始/峰值/结束, 100 ms 采样可能遗漏短时打开). 这些数字只描述该测试, 不能代替生产 RSS 与不同媒体大小的压测.
