# 用户流量记录

用户在「使用记录 → 流量记录」查看自己的 API 正文流量，管理员在「使用记录 → 流量记录」查看全站或指定用户。首版只统计，不改变 Token 计费、余额、套餐或收费规则。

## 计量范围

- 上传为网关从原始请求体读取的实际字节数；鉴权预读后重放给业务处理的正文不重复累计。未知 Content-Length 的请求仍按读取量计算。
- 下载为响应写入操作返回的字节数，包括 SSE 数据、心跳和错误响应。部分写入只累计实际返回的 `n`，不把整个计划响应作为已发送流量。
- 成功鉴权后，失败、取消、写入异常与 panic 也记录已观察到的流量。`completed` 仅表示 HTTP 处理结束，不证明 SSE 业务成功或远端完整接收。
- 未成功鉴权的请求不归属用户。HTTP 头、TLS/TCP 开销、重传、WebSocket、Live/WebRTC、外部媒体下载以及无 API Key 的能力链接下载不在首版范围内。返回媒体 URL 时只计算本站返回的正文。
- Serverless 由外部入口计量；经签名和重放保护验证的内部接收节点不重复计量。客户端伪造转发头或 Upgrade 头不能关闭普通 HTTP 计量。

只保存字节数、用户与 Key ID、路由模板、请求关联 ID、时间和结果；不保存正文、认证头、原始查询参数或能力链接令牌。单次请求按开始时间归属统计周期，在 HTTP 处理结束后生成记录，因此长请求和补偿写入会延迟反映在统计中。

## 日周月年查询

使用站点配置时区，日按小时、周和月按日、年按月展示；周一为一周开始。趋势中的每个柱子只统计该小时/天/月内的上传与下载流量；周视图是周一至周日每天各自的流量，不是从周一到当天的累计。柱内堆叠只表示同一时间桶的上传加下载，不跨桶累计；没有请求的时间桶显示零。上方汇总卡片则显示整个所选周期的总量。周期为左闭右开区间，支持闰年、夏令时及非整小时偏移。夏令时重复小时在趋势中保留不同 UTC 偏移。用户可切换历史周期，使用与用量明细相同的 API 密钥名称下拉搜索并分页查看请求；密钥列表仅来自当前登录用户，历史搜索包含已软删除密钥并标记“已删除”；用户接口忽略客户端传入的 `user_id`。管理员复用用量明细的邮箱与密钥名称搜索控件，密钥候选使用仅返回 ID、名称与删除标识的专用历史接口，选中用户后联动其密钥候选项，切换用户时清空已选密钥。选择或清空后立即查询并返回第一页；重置同时清除已输入但未选择的搜索词。接口仍提交用户和密钥 ID。

日期字段独立于时区解析，再映射到该日期的最早有效边界：午夜被跳过时取当天第一个有效时刻，午夜重复时取第一次。整日不存在的日期（例如 `Pacific/Apia` 的 2011 年 12 月 30 日）在日查询中返回 400，周/月趋势跳过空日并保持实际时间区间连续，避免日期推进停滞。

API 为 `GET /api/v1/usage/traffic` 和 `GET /api/v1/admin/usage/traffic`，参数如下：

| 参数 | 含义 |
| --- | --- |
| `period` | `day`、`week`、`month`、`year`，默认 `month` |
| `date` | 周期内的 `YYYY-MM-DD`，默认站点时区当天 |
| `api_key_id` | 可选正整数；用户接口始终叠加当前登录用户限制 |
| `user_id` | 仅管理员接口生效 |
| `page`、`page_size` | 旧客户端兼容：默认 1、20；上限 10000、100。新页面不发送 `page` |
| `view` | `all`（默认、兼容旧接口）、`summary`（汇总、趋势、首条时间）、`details`（仅明细） |
| `cursor` | 上一页返回的 `next_cursor`；与 `page>1` 或 `view=summary` 同用返回 400 |

返回上传、下载、总字节数、请求数、完整时间桶、分页明细、是否有下一页、统计时区及当前筛选下第一条记录时间 `recorded_since`。未采集的历史流量无法推算，`recorded_since` 不是无损覆盖承诺。原始字节数为整数，前端只在显示时换算 KiB/MiB/GiB。

新页面分别加载汇总与明细，一侧失败不隐藏另一侧；翻页只查询 `view=details`，保留当前汇总。汇总和明细是独立读取快照，实时新增数据可能让两者短暂不同步，刷新会重新读取两者。`view=all` 仍在同一快照内返回原始组合结果。`summary` 不执行明细查询；`details` 不计算趋势、总量或 `recorded_since`，这些字段的默认零/空值不代表实际汇总。

明细按 `(started_at DESC,event_id DESC)` 使用游标继续读取，避免新记录插入列表头部后导致下一页重复。游标仅是时间和事件 UUID 的位置，所有查询仍叠加当前用户/密钥条件，越出所选周期的游标返回 400；修改筛选或刷新后清空游标历史。下一页使用 `next_cursor`，没有下一页时不返回该字段；前端保存已访问页的输入游标以支持上一页。首个明细响应固定后续翻页的日历周期，跨午夜仍使用同一周期；首次汇总和明细跨越日历边界时重新对齐汇总。游标不是跨请求数据库快照，迟到补偿事件仍可能在后续页出现，已翻过位置的迟到事件需要刷新查看。旧 `page` 接口保留原 OFFSET 行为，不再用于新页面。

## 数据存储和补偿

迁移 `307_user_traffic.sql` 创建 `user_traffic_events` 与 `user_traffic_hourly`。事件使用独立服务端 UUID；相同 request ID 的客户端重试仍产生独立事件。数据库以一条原子 SQL 写入事件并累计小时桶，重放相同事件不会重复累计。查询使用一致性快照，小时桶覆盖完整 UTC 小时，原始事件补齐时区边界片段。新增 `308_user_traffic_cursor_indexes_notx.sql` 并发建立用户、密钥和全站的降序游标索引；保留旧索引以支持回滚，重复索引的清理应在实际执行计划/索引使用评估和回滚窗口结束后安排。

统计是额外的尽力记录，不参与主业务成功与否的判定。请求结束时只做元数据快照和容量为 1024 的内存队列非阻塞投递，不做磁盘、数据库、UUID 生成或日志操作。队列满、worker 已停止或不可用时直接跳过这条统计并增加对应计数，不等待后台恢复，也不为每个请求创建 goroutine。

固定一个后台 worker 生成事件 UUID，落盘后再异步入库；文件同步与原子改名均在后台进行。目录为数据目录下的 `user-traffic-pending/`，按照项目规则优先 `DATA_DIR`、其次可写的 `/app/data`、最后工作目录；目录解析、探测和创建也全部在后台。目录权限为 0700，事件文件为 0600。存储初始化失败会让统计降级，HTTP 服务继续启动；后台周期性重试，本地存储不可用时仅由 worker 尝试直接写数据库。

资源预算为：请求非阻塞投递后合并唤醒 worker，100ms 定时器只用于空闲检查，不再是每轮处理的固定间隔。每轮最多落盘 32 条新事件，并回放最多 4 批、每批 32 条补偿记录，为积压恢复留出余量；有新排队或可回放积压时继续工作。每次数据库操作超时 250ms，补偿轮次总预算 1 秒；仅预算耗尽不会引入失败退避，真实投递失败后至少等待 2 秒重试。

回放把一批事件合并成一条原子 SQL，仅对新插入事件按 UTC 小时及用户/密钥/分组聚合后更新汇总，支持同小时多事件、批内重复和整批重试。暂时性失败保留整批文件；永久 SQL 拒绝时在同一轮时间预算内逐条隔离，避免一条坏记录阻塞整批。文件格式仍是每事件一个 JSON，保留文件与目录同步，兼容旧版本补偿目录与二进制回滚。这里优化的是数据库往返和调度；逐事件文件同步仍可能成为瓶颈。补偿目录最多接纳 10000 个文件或 64MiB 逻辑文件大小，隔离文件和临时文件也计入预算，单事件最大 8KiB。达到任一目录预算后跳过新统计并计数，继续处理已有补偿文件。该限制约束本 worker 的新增文件，不自动删除旧文件，也不代表文件系统实际占用空间或阻止其他进程写入。每个副本应使用独立补偿目录。

部署时为补偿目录挂载持久卷并监控容量。数据库暂时不可用时，已经落盘的文件保留并在恢复或进程重启后重试，无需重放业务请求或调用上游。数据库写入仍共用现有连接池，但该 worker 同时最多占用一次写操作；后台 CPU、磁盘和连接池仍有资源开销，尚未进行生产吞吐压测。

- 无法解析、元数据校验失败或 PostgreSQL SQLSTATE `22` / `23` 永久拒绝的文件改为 `.json.invalid` 保留并告警，后续有效记录继续处理。未知测量版本同样隔离；修复原因后才能恢复 `.json` 后缀重试。
- 网络、事务、表结构未就绪和权限错误继续保留 `.json` 重试。后台本地落盘与数据库回退都失败时增加 `persistence_failures`，表示可能缺失；目录同步失败后文件也可能已经存在，不能将此计数解释为已核实的永久丢失条数。
- 退出时立即停止接收新统计，最多等待 1 秒排空；超时取消后台数据库操作，未处理事件计入退出丢弃。系统进入 drain 后，仍在完成的业务请求不受此规则阻断，但其统计可能被跳过。不可取消的文件系统调用可能延续到进程退出，退出调用方不会无限等待。
- worker panic 在后台恢复并标记故障，后续统计跳过且计数，不能让附加统计的 panic 终止业务进程。进程内计数无法覆盖强杀时遗失的内存事件。
- 正在进行的请求、已经入队但尚未落盘的记录、过载和异常退出都可能缺失。首版不能作为直接扣款账本；正式收费前必须另行设计可靠采集、完整性核验、在途恢复和对账。

首版不自动删除流量明细和汇总，诊断日志与 Token 用量清理不会联动删除这些表。不要直接清理事件表：事件 UUID 去重、非整小时边界查询和历史首条时间都依赖原始记录。后续保留策略需要同时设计归档、去重和汇总边界方案。

## 积压监控与告警

管理员流量页展示当前处理节点的状态，刷新或重新查询时更新；该卡片独立于报表请求，监控失败不会阻止查看流量。

`GET /api/v1/admin/usage/traffic/health` 仅管理员可访问，不返回文件路径、数据库错误详情或请求正文。接口只读原子计数与后台缓存，不扫描磁盘或访问数据库；磁盘快照正常每 2 秒更新，后台被慢存储拖住时快照也会变旧，应结合 `checked_at` 判断。返回：

| 字段 | 含义 |
| --- | --- |
| `queued_events`、`queue_capacity`、`processing_events` | 当前内存排队数、队列容量、当前批次尚在处理数 |
| `dropped_events` | 本进程跳过统计及持久化双重失败次数总和，表示可能缺失 |
| `queue_dropped_events`、`shutdown_dropped_events` | 队列满、退出或 worker 停止后跳过次数 |
| `spool_limit_dropped_events`、`invalid_dropped_events`、`unavailable_dropped_events` | 目录预算、无效事件、未初始化导致的跳过次数 |
| `worker_running`、`worker_panics`、`storage_available` | worker 是否运行、panic 次数、最近存储检查是否可用 |
| `pending_events`、`quarantined_events` | 当前缓存中的待入库文件数与隔离文件数 |
| `oldest_pending_at`、`oldest_pending_age_seconds` | 最老文件修改时间及等待秒数，用于诊断，不是统计归属时间 |
| `delivered_events`、`last_delivery_at` | 本进程成功投递次数及最近时间；幂等重放也计一次操作 |
| `delivery_failures`、`staging_failures`、`persistence_failures` | 数据库投递失败、本地落盘失败、二者同时失败次数（数据库失败以操作计数，一次批量失败可能影响多条事件） |
| `checked_at`、`status` | 后台磁盘快照时间及 `ok` / `delayed` / `degraded` 状态 |

队列达到一半、待入库达到 256 条或最老积压达到 60 秒时为 `delayed`；存储不可用、worker 停止、出现跳过/潜在丢失计数或隔离文件时为 `degraded`。后台约每 30 秒输出异常汇总 `DELIVERY ALERT`，不在请求路径输出告警。可接入现有日志告警系统，本功能不主动发送邮件或外部通知。

目录不可用或 worker 未初始化时返回 HTTP 200 的明确 `degraded` 状态，不把它伪装成零积压的正常状态。页面展示队列、丢弃与存储故障提示，报表仍可查询。计数器为近似并发快照，重启归零；文件数在后台重新扫描。多副本需逐节点监控，负载均衡后的单次响应不是全站汇总。

历史密钥搜索接口为 `GET /api/v1/usage/traffic/keys` 及管理员对应路径，支持名称参数 `q`（也可传 `#ID` 精确查找）；管理员可额外传 `user_id`。每次最多 30 个匹配候选，活动密钥优先；输入名称缩小范围，或直接按明细中的 `#ID` 定位重名密钥。只返回 ID、名称和删除标识，不包含密钥值、认证信息或账户设置。原密钥管理接口的删除过滤保持不变。

## 验证和页面复核

离线 mock 测试覆盖普通 HTTP、SSE、预读重放、未知长度、取消、部分写入、Flush 失败、panic、伪造头和内部转发。补偿测试覆盖数据库故障、重启、有界队列满、慢存储、目录解析阻塞、缓存健康读取、退出预算、worker panic、目录预算和并发退出。真实 Gin 中间件回归在后台存储被卡住并填满队列时，仍验证业务返回 HTTP 200。PostgreSQL 测试使用单连接 `pg_temp` 表，验证迁移重复执行、幂等汇总、事务回滚、用户隔离、分页、非整小时偏移和夏令时重复小时。

panic 请求在生产 Recovery 完成响应后结算，包含恢复时写入的错误 JSON；已经写出正文或连接断开时仍遵循原恢复行为，不追加错误正文。回归用例覆盖 500 正文计量、部分正文后 panic、broken pipe、连续请求不重复结算，以及跳日整月查询、午夜缺失与午夜重复。

## 容量核查与归档边界

提供只读脚本 `backend/scripts/user-traffic-audit.sql`：显示两张表及索引的实际占用和估算行数，并在同一个只读一致性快照内核对上一完整 UTC 小时的原始事件与小时汇总，最多列出 100 处差异，语句超时 30 秒。通过 `psql -X -v ON_ERROR_STOP=1 -f backend/scripts/user-traffic-audit.sql` 显式运行，连接参数由运维环境提供；脚本不改写或清理数据，也不能检测从未采集的请求。估算行数依赖 PostgreSQL 统计信息，不是精确计数。

以实际存储增长估算预算：每日新增事件约为平均请求数/秒 × 86400；平均 100 请求/秒就是 864 万条/日。结合表和索引每日增量、备份与 WAL 占用设置容量告警，不用本地压测速度推算生产容量。无自动删除策略，避免未经确认的保留期限导致历史数据丢失。

归档上线前必须同时满足：原始明细仍可按用户和游标查询；非整小时边界查询能够读取归档；事件 UUID 去重记录覆盖可能迟到/重放的全部时间范围；首条时间元数据不因迁移变化；归档前后按小时核对请求数与上下行字节一致，并验证恢复和回滚。单独删除原始事件、只保留小时汇总，或按 `started_at` 截断去重记录均不安全。当前只读核对脚本是后续归档的验证工具，不意味着已经实现归档或可直接清理历史表。
