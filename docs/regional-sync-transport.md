# 区域全量同步传输基础（PR 3a）

依赖已合并的 #419 和 #420。原计划 PR 3 拆成 3a（本 PR：可测试的同步传输及持久版本）和 3b（主站数据库发布映射、领域校验、调度/鉴权激活及后台同步工作器）。因此整体预计至少八个 PR；本 PR 不代表完整配置同步已上线。

## 已实现

- `Codec`：AES-256-GCM 加密且校验完整快照信封，key ID 作为认证附加数据。每次生成随机 nonce；支持多个 key ID 便于重叠轮换。未知 key、错误 key、密文篡改拒绝。此为共享密钥对等认证，不是只有主站可签名的非对称协议。
- `Replica`：独占一个 `(region_id, kind)` 流及本地状态文件，接收方先验证信封 schema、区域、版本、时间、摘要及必需的领域校验回调，再写临时文件、fsync、原子 rename 和目录 fsync，最后发布内存视图。任意持久化失败后本进程停止提供旧视图，需重新打开恢复。
- 全量替换而不是 patch：最新文档不再包含的对象即删除/撤销。领域消费者必须完整替换视图，不能把缺失对象合并保留。传输层不定义领域删除字段或生产 API Key 内容。
- 同版本同内容幂等；同版本不同内容和旧版本拒绝。重复请求不延长快照有效期。
- 重启恢复加密文件；过期文件保留版本下限但不提供数据。正常重启文件缺失或损坏即失败；只有明确 bootstrap 可接受文件不存在。禁止在每次启动自动 bootstrap。
- `Publish`：由调用者提供持久化分配的 revision 和一致性导出的全量 payload，封装并持久化发布。不会从业务数据库读取或分配版本。
- `Handler` 与 `Pull`：提供全量加密信封的 GET 服务和一次 HTTPS 拉取。拉取上限 8 MiB、明文信封上限 4 MiB，超时 15 秒，拒绝重定向和包含凭据/查询/片段的 URL。领域消费者可以设更小限制。

## 接入约束

没有注册公共 HTTP 路由、环境开关或启动任务。Handler 必须在 TLS 和客户端认证（例如 mTLS）之后挂载。Pull 的 Transport 由调用者提供受信任 TLS/mTLS 配置；不能关闭证书验证。域名、CA 和区域密钥来自可信部署配置，不接受用户提供的地址。公网未认证 HTTP 端点不可直接挂载。

每个区域使用独立的随机 32 字节密钥；密钥仅通过受限 Secret 注入，不进入配置快照或日志。区域持钥者能构造该区域快照，因此区域进程属于信任边界。若要防区域节点伪造控制面内容，需要后续增加非对称签名。

每个 Replica 独占一个文件及父目录（建议 0700），状态文件 0600；不支持多个进程共享同一路径或不提供 POSIX 原子 rename/fsync 语义的文件系统。历史备份被回滚不是本地版本文件可检测的问题；恢复备份后必须从权威端重新确认版本下限再开放准入。状态文件中是密文。保留旧解密 key 直至发布新版本并完成各节点持久状态迁移；相同版本重试不会重写旧 key 密文。

`PayloadValidator` 强制提供，但不能用“JSON 合法”代替领域验证。回调必须确定、无副作用；输入为副本。PR 3b 需校验 API Key 撤销、用户和分组关系、账号区域归属、凭证字段白名单及全量一致性。现有测试中的 ids 数组是虚构协议，仅测试传输删除语义，不是应用 schema。

尚未实现：增量游标、主站导出事务/版本分配、调度 bucket 批量激活、auth 消费者、跨流一致性屏障、后台退避重试/监控、磁盘防回滚外部锚点、账号所有权。当前不能与 #420 直接拼装即上线；特别是账号凭证补全、分组和计费仍未区域化。

## 验证

离线测试覆盖密文篡改、错误 key、重叠 key 轮换、HTTPS 全量删除、重定向拒绝、同版本冲突、文件丢失/损坏、持久化失败、过期重启及版本防倒退、并发版本单调性。未连接主站数据库、生产 Secret 或真实模型请求。
