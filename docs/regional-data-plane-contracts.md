# 多区域数据面：协议基础与交付顺序

## 目标及当前边界

目标是让 `us.tosky.io` 的正常模型请求在美国本地完成鉴权、候选读取、并发检查和额度预留；主站管理用户、配置和全局账本，跨区同步不进入每次请求的关键路径。

本 PR（第 1 步）仅新增 `backend/internal/regional` 的协议类型与校验。没有修改 `RuntimeConfig`，没有新增可启用的环境变量、HTTP 端点、数据库迁移或后台任务。`Config` 是未来协议消费者使用的策略模型，不是已经接入应用的运行开关；其零值不可用于区域服务。现有 `full/gateway` 角色和 `serverless` 路由继续使用原路径。不要把合并本 PR 当作美国节点已经可独立处理请求。

## 快照与同步

- schema 版本固定为 `1`，未知版本拒绝。
- `region_id` 为 1–63 字符的 ASCII 字母、数字、下划线或连字符，首字符必须是字母或数字。它标识一个共享本地账本的区域，不是 Pod ID。
- 快照按 `(region_id, kind)` 分流；`kind` 分别为 `auth` 和 `scheduler`。
- 每条流有持久化单调递增 `revision`（JSON 十进制字符串）；初次加载的当前版本为零。拒绝重复或倒退激活；同步重试可以对完全相同的已接受快照确认成功，但不能延长原有效期。相同版本不同内容必须报警并拒绝。
- 激活前验证 schema、区域、流类型、版本、生成时间、过期时间和 SHA-256。Payload 为 JSON 数据的原始字节，信封 JSON 中通过 base64 编码，避免 JSON 重编码影响摘要；摘要不提供来源认证。
- 消费者策略限制最大快照年龄（1–86400 秒）和生成时间的最大未来偏差（0–60 秒）。示例值为最大年龄 60 秒、偏差 2 秒，实际配置需结合撤销时限验收。偏差绝不延长到期时间。到期边界拒绝新请求。
- 同步层必须认证发布方，并限制信封大小、校验 payload 的领域结构后，再原子写入 payload 和 revision。此 PR 尚未定义具体 auth/scheduler payload，不允许直接信任任意 JSON。
- 重启只能恢复未过期的持久快照；不能用进程启动时间刷新年龄。发布端恢复备份后不得重置版本；灾难恢复需单独的管理流程。
- Auth 快照用于本地 API Key 验证与权限。Key 校验材料、账号凭证等内容仍属秘密；禁止放到公开日志、指标或 PR 样例。传输认证、载荷加密与密钥轮换在同步 PR 中实现。
- 封禁和撤销存在同步窗口。后续同步 PR 必须支持删除/撤销以及区域确认，并测量最大窗口。断连且快照过期时拒绝新请求，不能偷偷回源主站。
- 校验函数只用于激活；本地读路径还必须持续检查已接受快照的有效期。跨 auth/scheduler 流的关联对象完整性也必须由消费者校验，不假设两条流天然原子一致。

## 区域额度与用量

`Lease` 表示主站已经预留的用户 USD 额度，唯一绑定 `lease_id + region_id + user_id`。金额以整数的十亿分之一美元计，JSON 使用十进制字符串，避免浮点和 JavaScript 精度丢失；最大值为 int64 上限。不允许负数。现有浮点余额的转换、舍入策略、定价快照和溢出检查需在账本 PR 明确并测试，不能直接 float64 强转。

- 主站必须先在事务内预留额度，再发布租约；重复申请需使用稳定幂等键，不能再次预留。
- 区域内所有 Pod 共享同一本地账本，不能各自获得全额副本。额度耗尽或租约过期时拒绝新请求；后台续领不能阻塞每次请求。
- 发起上游请求前，本地持久化预留该请求的保守费用上限。无法确定上限的请求在首版不开放。完成后将预留转为实际消耗，并在同一本地事务写入待回传事件。
- `UsageEvent` 为一次最终费用，字段包含全局唯一 `usage_event_id`（建议 UUID）、租约、区域、用户、Key、上游账号、接纳/完成时间和费用。
- 后续 `UsageEvent` payload 需扩充原始用量、模型及定价版本，使主站可独立对账；当前类型仅提供稳定的事件身份和租约边界，不替代现有完整 UsageLog。
- 验证单个事件不等于限制累计花费。区域账本必须原子校验累计消耗与在途预留总和不超过租约。当前 `ValidateAgainst` 不做存储、幂等、鉴权或余额扣减。
- 接纳时间须落在租约的 `[issued_at, expires_at)` 区间。已接纳流可以在到期后完成，结算仍须接受对应事件；租约过期不等于可以归还全部额度。
- 用量至少一次回传，原事件 ID 和内容保持不变。主站全局唯一约束去重；同 ID 不同内容拒绝，不能将冲突当成功。确认记录持久化后才清理区域 outbox。
- 节点崩溃留下的在途预留不能直接释放并重试上游。需按请求状态对账，无法确认时保留占用或进入人工恢复流程。租约关闭、迟到事件、未使用额度返还需独立状态机，不能仅依赖 TTL。
- 第一个可上线版本限定余额付费路径。订阅日/周/月额度、API Key 预算、账号费用限额、退款及价格变化需明确处理；未支持的路径拒绝区域接纳，不能绕过校验。

## 账号与跨区并发

首版建议上游账号独占区域，区域内以本地 Redis 协调并发、冷却和粘性；一个账号的 OAuth 刷新只有一个所有者。快照同步不代表跨区同时使用账号已安全。账号迁移先停止旧区域接纳并排空在途请求，再移交所有权和凭证。若后续需要跨区共享账号，应另行设计并发额度租约、所有权 fencing 和凭证版本。

## 七个 PR 的交付边界

| 步骤 | 仓库与内容 | 验收门槛 |
| --- | --- | --- |
| 1（本 PR） | sub2api：协议与策略模型 | 拒绝过期/倒退/篡改快照、错误租约及损失精度的金额；现有请求路径不变 |
| 2 | sub2api：本地调度快照与读取接口 | 原子替换、候选完整性、持续过期检查；测试关键路径无远程读取 |
| 3 | sub2api：主站发布与区域同步 | 全量、增量、撤销、恢复、认证、领域校验、持久版本及必要的跨流一致性 |
| 4 | sub2api：本地鉴权、并发和区域准入 | 不访问主站；所有未支持的计费类型被阻止；账号所有权受控 |
| 5 | sub2api：主站与区域账本、持久 outbox | 双区域不能重复花费；重试去重、冲突、崩溃、迟到事件及租约关闭对账通过 |
| 6 | sub2api-operate：美国集群部署 | 固定镜像 SHA、本地区域存储、密钥注入、备份、同步及账本观测、恢复与回滚 |
| 7 | sub2api / sub2api-operate：灰度与验收 | 真实模型首 token/错误率、断连测试、计费对账；具备停止接纳与排空流程 |

第 2 和第 3 步可以在协议基础上开发，但第 2 步在真实同步接入前只能用于隔离测试。第 4 步需要第 2/3 步，并受第 5 步额度能力约束；第 5 步可提前开发，但必须与本地鉴权、账号所有权一起验收。第 6 步可先准备部署清单，开放生产业务必须等第 2–5 步通过。第 7 步上线门槛依赖全部。

开发不自动意味着合并、发布或部署。#415 仅优化现有 Redis 往返，运维 #6 仅提供测试基线，两者都不能替代上述能力。

## 本 PR 的离线验证

测试只使用虚构标识及时间，覆盖快照激活边界、信封重编码后摘要保持、整数金额 JSON 精度、租约与事件匹配、租约到期后的已接纳请求完成。未验证快照网络同步、真实扣费或生产延迟。
