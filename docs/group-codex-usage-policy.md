# 分组 Codex 使用策略

在管理后台的分组创建或编辑页配置以下策略。新建分组和升级前的已有分组默认不启用这两项开关。

| 设置 | 行为 |
| --- | --- |
| 仅允许 Codex 客户端 | 复用全局 Codex 客户端识别、版本和指纹策略，在员工 API 入口拒绝不匹配的请求，返回 `403 / codex_client_required`。 |
| 禁止子代理 | 拒绝携带 Codex 子代理或父线程标识的员工请求，返回 `403 / subagents_blocked`。可以独立开启，无须同时启用客户端限制。 |
| 思考强度上限 | OpenAI 和合成分组新增 `ultra` 档位，顺序为 `minimal < low < medium < high < xhigh < max < ultra`。超过上限时沿用降档或拒绝策略。Anthropic 分组的可选档位保持到 `max`。 |
| 思考强度映射 | 可配置 `ultra → deny` 仅拒绝 ultra，或 `ultra → high` 等降档规则。仍按模型匹配规则先映射，再检查上限。 |

例如，要保留普通 Codex 使用并控制额外消耗，可开启「仅允许 Codex 客户端」和「禁止子代理」，将思考强度上限设为 `max`，超限动作设为「拒绝」。选择「自动降档」则将显式 ultra 请求改为 max。关闭限制或提高上限由管理员决定，不会自动修改已有分组。

这些入口策略覆盖 HTTP 别名和 Responses WebSocket 的首帧及后续帧。修改客户端、子代理或思考强度策略后，排队请求和已有 WebSocket 在下一次授权复核时需要重新准入；不会撤回已经发往上游的推理。

账号管理的「测试连接」「智商测试」以及质量运维的探测和 AI 判题使用内部服务调用，不经过员工 API 入口，仍可按同一分组选择账号。没有外部请求头可以申请内部豁免。

子代理识别使用 `x-openai-subagent`、`x-codex-parent-thread-id`、`x-codex-turn-metadata` 中的 `subagent_kind` / `parent_thread_id`，以及请求体 `client_metadata` 中的对应字段。正常主线程、预热、压缩和提示词中提及子代理不会单独触发限制。自动审查等带子代理标识的请求也会被拒绝。

启用运维监控后，被禁止的子代理请求会出现在「使用记录 → 错误请求」中，保留用户、API Key、原始分组、模型、IP、时间和请求 ID，可按用户、Key、分组及 `403` 筛选。详情包含 `subagents_blocked`，不保存提示词或完整请求体。HTTP 返回 `403`；WebSocket 升级后仍以 `1008` 关闭，错误记录使用逻辑状态码 `403`。这些记录属于客户端策略拒绝，不计入服务故障 SLA，不归因于上游账号；独立的入口拒绝聚合统计继续保留。升级前已聚合的拒绝记录无法还原逐条请求明细，不自动回填。

客户端指纹和子代理标识由客户端提供，不能证明软件来源，也不能可靠识别主动删除所有标识的客户端。ultra 限制针对显式 effort 字段和客户端公开模型名的 ultra 后缀；合成路由改写模型名后仍按原公开模型执行后缀判断与模型范围匹配。`/v1/messages` 省略 `output_config.effort` 时，显式 ultra 后缀也会在调度前执行拒绝或降档；降档只映射一次。显式 effort 优先于后缀，普通省略值保留现有上游默认行为。此策略不能对客户端本地运行的工具或并发活动做绝对限制。

迁移仅追加 `groups.codex_cli_only` 和 `groups.block_subagents` 两个非空布尔字段，默认值均为 false；鉴权缓存版本更新为 29。复制分组保留这些策略。回退二进制不会撤销数据库字段，旧二进制也不会执行新增准入策略。
