# Astra 门票糖果观测（Beta）

在「自动打票策略」中启用「启用糖果测试验证使用后的票据」后生效，默认关闭。保存时省略该字段保留原值；关闭后不再发送新的观测请求，已经发出的请求在原期限内完成。

完整续接探针通过，只能说明当时的门票协议检查通过。糖果题是额外的质量样本，不能保证后续请求都保持相同质量。

已入库、通过探针的 SSE Astra 门票被真实 HTTP 请求使用后，在上游返回 HTTP 200、业务响应关闭并释放出口占用时，后台尝试发送一发糖果题。没有业务请求时不主动测。该观测使用对应账号、门票、路由 Cookie 和已记录出口，发送独立题目，不复制业务对话。

观测结果展示在「打票全流程 → 号池调度」和流程事件中，标注 Beta。答错、网络失败、超时、门票重签、路由变化和响应模型不符分别记录。原有号池加入/移出统计不包含这些事件。

这项能力只写观测事件，不修改门票、账号、模型映射、冷却、分组或调度开关，不触发业务重试。业务请求不等待观测结果，观测中的上游错误也不返回给用户。

## 开销和边界

- 适用于 `gpt-6-astra` 的已验证 780 门票、SSE 传输。其他票形、模型、WebSocket 和手动探针不自动触发。
- 每个进程对相同票据材料最多观测一次。换票可以产生新样本；重启后会重新观测，去重不是持久化保证。
- 最多同时运行 2 个观测，最多保留 2048 个未到期去重记录，满载直接跳过，后续业务请求可以再次尝试。没有后台排队或自动重试。
- 业务流结束时票已过期就不测；等待出口期间过期、账号身份改变或采票关闭，记录跳过原因。
- 每次最多增加一发上游模型请求，可能消耗账号额度，不进入用户请求用量和计费记录。总期限 45 秒，单次模型调用沿用已有探针超时；请求结束后的观测使用独立超时。
- 额外请求仍消耗网络、上游和出口资源；并发限制并不代表零资源开销。
- 只保存固定结果码和账号/模型/时间等流程元数据，不保存糖果输出、票据、Cookie 或认证头。
- 展示历史观测，不用它替代当前门票有效性、号池状态或手工质量测试。页面组件截图使用虚构数据，未验证生产上游质量。

回滚代码即可停止新增观测，无数据库迁移；旧版可能隐藏新增的流程事件类型。
