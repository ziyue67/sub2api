# Excel / BPS 在途上限与预算联动

PR #91 保留 #83 的请求体限额、共享预算、在途上限配置，以及未知长度正文渐进预留、压缩正文读取后缩减预留的修复。复用 `excel_bps_image_max_requests`，不再新增 `excel_bps_image_relay_max_requests`。

采用作者压测配置作为新默认值：在途上限 128、共享预算 1024 MiB，在途范围为 1–512。实际准入预算为 `max(配置的共享预算, 在途上限 × 8 MiB)`；128 槽至少使用 1024 MiB 记账预算，512 槽至少使用 4096 MiB。预算用于正文及处理副本的估算，不是预分配内存，也不是进程 RSS 限额。较大的显式共享预算仍生效。调整配置后，新请求读取最新值；调低上限不会中断已有请求，但会限制后续准入，直到已有预留释放。

## 作者提供的压测结果

来源：[PR #91](https://github.com/ranxi2001/sub2api/pull/91) 正文及维护者收到的作者压测截图。下表是作者原分支的测试报告，不是本次整合分支的实测。测试使用 128 槽与联动预算，BPS 通道模型为 gpt-6-astra。

| 场景 | 作者报告结果 |
| --- | --- |
| 纯文本 100 并发 | 100/100 成功，534 请求/分钟；账号并发峰值 93/100，测试 Key 在途峰值 100；平均延迟 5.9 秒，p95 7.9 秒 |
| 带图 100 并发（663 KB 图片 × 100） | 80 个 HTTP 200、19 个 HTTP 429、1 个客户端连接异常；账号并发峰值 56/100，平均延迟 16.7 秒；网关侧无 503 |
| 资源与清理 | 报告 CPU 0.26%、内存 97 MB；100 张图片后台清理完成，暂存目录剩余 656 KB |

作者报告将 429 归因于上游返回的 `Rate limit exceeded`。截图未提供资源采样方法或完整时序，不能将资源数值视为所有负载下的峰值；该测试也未验证 512 并发。这里采用的是其预算联动机制与配置上限，不把原分支压测结果当作整合后的吞吐保证。

## 本地回归范围

离线测试覆盖：默认 128 槽与 1024 MiB 预算；128 槽不再被显式配置的 512 MiB 预算提前卡在 64 个小请求；较大正文仍受有效预算约束；较大的显式预算被保留；512 槽的准入及超额拒绝；调低配置后的释放和恢复；设置保存及前端 512/513 边界。测试不向上游发出请求，不代表真实 512 并发压测。

新默认值适用于新安装与尚未保存这些字段的实例。已有明确保存的容量配置保持原值，管理员可在设置页调整。
