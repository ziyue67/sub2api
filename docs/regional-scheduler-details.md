# 区域调度详情读取（开发中）

此改动将调度快照扩展为包含分组策略。候选列表仍携带完整账号结构，包括凭证，但以前 `GetAccount`、`GetAccounts` 和 `GetGroupByID*` 会向主站 Redis/PostgreSQL 补全。区域本地读取器接入后，这些方法只读同一份已认证、持久且未过期的快照；缺项、过期、状态文件失败或旧快照没有分组策略时拒绝，绝不回源。重复账号如果在不同桶携带冲突的凭证或状态，整份快照拒绝激活。

这还不是美国请求链路。网关模型准入仍是 503；直接使用 `accountRepo`、`groupRepo` 的其他调用，以及账号并发、状态写入、OAuth 刷新、租约和账单均需独立审计和实现。发布端静态 `allowed_account_ids` 只限制导出，不提供跨区域并发协调。最终采用共享账号池，不做账号区域独占或强制迁移：需要主站后台分配区域并发槽位，并让主站自身也遵守已租出槽位；统一后台刷新凭证，区域同步读取。不要把这个改动作为开放生产流量的依据。
