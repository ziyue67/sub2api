# 邮箱别名注册拦截

后台入口：**系统设置 → 安全与认证 → 注册设置 → 屏蔽邮箱别名注册**。

开关默认开启，包括升级前没有该设置的部署；无需数据库结构迁移。关闭并保存后允许别名格式参与注册，但现有的同一收件箱别名去重仍然生效，不能用多个别名重复注册。

| 地址示例 | 开启时的注册行为 |
| --- | --- |
| `sa.m.ple@gmail.com`、`sa.m.ple@googlemail.com` | 拒绝；请去掉用户名中的点号 |
| `sample+tag@gmail.com`、`sample+tag@example.com` | 拒绝；请去掉 `+tag` |
| `sample@gmail.com.` | 拒绝；请去掉域名末尾的点号 |
| `first.last@example.com` | 允许通过别名检查；仍须符合其他注册规则 |
| `sample@gmail.com` | 允许通过别名检查；仍须符合其他注册规则 |

该规则按地址格式拦截，不能据此判断用户是否滥用。首次注册使用带点号 Gmail 的正常用户也会被要求改用不带点号的地址；其他域名用户名中的点号保持有效。Gmail/Googlemail 的判断忽略大小写，只匹配完整域名，不能用子域名或相似域名触发同样规则。

检查在服务端执行，覆盖邮箱密码注册、注册验证码发送、第三方补充邮箱的新用户注册、已验证邮箱注册和首次 OAuth 自动建号；已有账号的登录、找回密码和资料绑定流程不使用这个新开关。管理员创建账号也不受此注册开关限制。

API 字段为 `registration_email_alias_block_enabled`，在管理员设置 GET/PUT 中返回布尔值；PUT 省略字段时保留原值，显式 `false` 才关闭。设置缺失、异常值或运行时查询失败时按开启处理。拦截返回 HTTP 400，原因码 `EMAIL_ALIAS_NOT_ALLOWED`；已有格式校验先拒绝的非法地址可能返回原有格式错误。

## 验收步骤

1. 使用隔离测试环境，进入上述后台入口，确认初始开关开启。
2. 使用点号 Gmail 或 `+tag` 地址注册或请求注册验证码，确认拒绝且不发送邮件、不创建账号。
3. 使用普通 Gmail 或企业邮箱 `first.last@example.com`，确认可以通过别名检查。
4. 关闭开关并保存、刷新，确认状态保留；使用尚未占用的别名邮箱注册，确认恢复原有注册流程。同一收件箱已有账号时仍拒绝重复注册。
5. 用已有的带点号 Gmail 账号登录，确认不受影响。
