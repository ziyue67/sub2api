# IP 风控第一版

## 范围与规则

后台「系统设置 → 安全与认证 → IP 风控」统一管理规则、自动封禁和认证访问记录。默认关闭；先使用观察模式核对代理 IP 与误报，再启用实际拦截。

优先级：运维应急关闭 → IP 白名单 → 手动 IP/CIDR 黑名单 → 国家地区 → 认证入口 UA → 自动封禁 → 认证请求频率。启用本模块时白名单在观察/实际拦截两种模式均豁免 IP 风控（包括原有登录 IP 临时封禁）；不会绕过认证、验证码、原有接口容量限制或数据库注册配额。模块关闭或应急关闭时原有防护恢复独立工作。上游「登录限流」开关独立控制原有登录容量限制和登录 IP 防护，不关闭本模块的黑白名单、地区、UA 与自动封禁规则；关闭 IP 风控后仍尊重该登录限流开关。

- IP：支持 IPv4、IPv6 和 CIDR。自动计数默认把 IPv6 汇聚到 /64，可改成 /64～/128；IPv4 映射 IPv6 按 IPv4 处理。手动规则支持备注、启停和到期时间。
- 自动封禁：登录请求数、明确的凭证验证失败、注册尝试、注册失败、验证码/找回密码请求分别配置窗口与阈值。成功登录不清空失败历史；5xx 不计作验证失败。封禁期限固定，重复请求不续期；触发封禁的计数器会清零，避免短封禁到期后被同一旧计数立即再封。
- 自动封禁作用于新请求（下述机器回调豁免），包括持有有效登录凭证或 API Key 的请求；既有流/WS 不主动断开。
- UA：记录认证访问及拦截请求的 UA；大小写无关子串匹配与空 UA 拒绝可配置，只作用于认证入口，SDK 模型请求不受 UA 规则影响。UA 不是浏览器真实性证明。
- 国家：复用服务端 GeoJS IP 解析与 Redis 缓存，不信任国家请求头。只有配置了国家规则才查询；启用会将公网客户端 IP 发送到 GeoJS。支持 `allowed_countries` 仅允许地区列表，留空不限制；例如 `["CN"]` 仅允许中国公网 IP，其他国家及未知归属一律拒绝。GeoJS 每实例同时最多处理 8 个查询，超出的新 IP 可能被视为未知；高并发冷缓存需在观察模式下验证。国家黑名单与允许名单不可包含相同代码；只有黑名单时，未知归属按开关处理。IP 白名单优先，私网地址不进行国家拦截。严格允许列表依赖 GeoJS 的可用性与准确性，查询超时也会拒绝，不能保证中国用户始终可访问。
- 可信 IP：始终使用 `server.trusted_proxies` 验证的代理链，或经签名验证的 serverless 原始 IP，不使用原始转发头兼容模式。未配置时仅信任本机 `127.0.0.1/32` 和 `::1/128`，支持本机 Nginx / 1Panel 转发真实访客 IP；本机进程处于这一信任边界内。显式列表替换默认值，显式空列表禁用信任，非法配置禁用信任，Docker 桥接和远程代理仍需显式配置。入口代理必须覆盖 `X-Real-IP` 并覆盖 `X-Forwarded-For` 或在末尾追加真实对端；源站端口应限制到可信入口。可信代理配置修改需重启，区别于风控规则保存生效。客户端 IP 使用真实来源，TCP 对端保留代理地址；旧记录及已有配额不自动改写。

## 数据、运行与故障策略

- 配置复用 PostgreSQL settings，无需新表或 Ent 代码生成；每实例每 5 秒后台刷新（含空闲节点），每次数据库读取预算 1 秒；保存本机后续新请求立即生效，其他节点在下一次成功刷新后生效，正常约 5 秒加读取时间。数据库故障期间不能保证同步时限，页面会显示配置刷新异常。数据库 IO 不持请求缓存锁，保存版本防止旧刷新覆盖新配置。
- Redis 原子计数和封禁保证多实例一致；观察模式与实际拦截使用独立计数/封禁空间。
- 管理员解封会清空新模块的两种模式计数、封禁以及对应的原有登录 IP 临时封禁/失败计数，避免观察模式下「已解封仍被旧规则拒绝」。原有 IPv6 登录防护按 /64 汇聚，清理对应的旧封禁也采用该范围。
- 认证事件只记录时间、IP、汇聚网段、TCP 对端、IP 来源、国家、方法、路由、UA、HTTP 状态、服务端错误原因和风控决定，不记录账号、密码、令牌、查询参数或请求正文。
- 事件流最多 2000 条，保留时间可配置为 1～720 小时；支持分页查询（默认每页 20 条，最多 1000 条），可按 IP、登录/注册/验证码类型、风控原因筛选和清空，先筛选再计算总数与分页。每种模式显示最近最多 500 条活动封禁并支持解封、清计数。敏感读取及变更进入既有管理员审计。
- Redis 不可用时，实际拦截模式的认证入口返回 503；普通页面、模型 API、管理请求降级跳过动态自动封禁，可判定的手动 IP / 国家 / UA 规则仍执行。动态 Redis 检查限时 150ms，故障退避 1 秒，避免故障拖慢每个请求；请求者取消不会触发共享退避。观察模式继续，原有安全限制仍生效。存储不可用的事件不再写 Redis，避免重复等待。配置刷新失败保留最后有效配置；启动首次加载失败默认关闭新风控并报告 `configuration_refresh_failed`，优先保障主流程可用性。
- `GET /health` 与已独立鉴权的内部探针不受影响。明确列举的支付 webhook、`GET/HEAD /api/bps-images/:token`、14 个 `POST /api/v1/internal/openai-reauth/*` worker 路由豁免整个新风控，继续由原有支付签名、短时能力 token 和 worker token 验证；按注册路由和方法精确匹配，不豁免任意同前缀路径。这样地区限制不会破坏支付入账、上游取图及内部自动授权。
- 防误锁：实际拦截模式下，保存会拒绝封锁当前管理员 IP/国家的配置；拒绝未知国家时也检查当前管理员。不要把整个代理或 CDN 出口网段误当作客户端封禁。
- 应急恢复：服务器设置 `IP_RISK_DISABLED=true` 并重启，停止本模块拦截，但后台仍能读取原配置并修复，避免默认配置覆盖原名单；后台修正规则后移除此变量并重启。该开关不禁用原有认证防护。

## 验收与后续

覆盖可信代理/伪造头、IPv4/IPv6/CIDR、白名单优先级、UA 范围、国家未知策略、观察模式、登录成功/失败、OAuth 注册、并发计数、固定过期、解封清计数、多实例、Redis 故障与日志边界。只用隔离 Redis/mock，不调用真实支付、邮件或付费模型。

可后续追加本地 GeoIP 数据库、ASN/机房规则、账号维度风险评分、验证码升级挑战与外部告警。本版不凭 UA 断言机器人，不凭 IP 唯一识别人，也不替代 CDN/WAF 的流量防护。

## 使用步骤

Docker + 宿主机 Nginx 部署先参照 [可信代理配置与注册 IP 配额排障](docker-trusted-proxies.md)，确认容器实际 TCP 对端及 `.env` / 持久化 YAML 的优先级。管理员接口 `GET /api/v1/admin/settings/ip-risk` 的 `current_ip` 与注册配额使用同一可信 IP 解析函数，`current_peer_ip` 返回当前请求的 TCP 对端，便于识别网关聚合；这些字段不依赖风控开关开启。

1. 部署前确认 `server.trusted_proxies` 只包含实际入口代理 IP/CIDR，入口覆盖客户端提交的转发头；核对管理页面显示的当前 IP 是否为真实访问来源。
2. 打开「系统设置 → 安全与认证 → IP 风控与访问记录」，加载配置。把管理员固定出口及需要豁免的可信来源加入白名单，设置 IP、国家、UA 规则和各自阈值。
3. 开启风控并保留观察模式，保存后查看登录、注册和验证码分类记录。使用「测试已保存规则」检查单个 IP/UA，不会增加计数；配置了国家规则时可能发起 GeoJS 查询。
4. 确认无误报后取消观察模式并保存。明确凭证失败达到阈值后，该次请求仍返回原认证结果，之后的新请求返回 429；临时封禁有固定期限和 `Retry-After`，手动 IP、国家和 UA 拒绝返回 403。
5. 点击“维护黑名单”查看规则列表，列表展示网段、备注、状态和到期时间，操作列支持修改、删除；点击顶部“新增”或行内“修改”填写规则表单，保存规则返回列表，取消表单仅丢弃本次编辑；“应用到配置草稿”后需保存 IP 风控配置才会生效，取消或按 Escape 关闭会丢弃本次弹框修改。
6. 自动封禁阈值、匿名 API 防护、国家 / 地区及 UA 规则、封禁列表和规则测试支持独立展开 / 收起，默认收起；折叠保留草稿，保存时会展开含无效输入的配置区。活动封禁可在对应列表解封并清计数，清空事件不会解除封禁。

管理接口均位于 `/api/v1/admin/settings/ip-risk`，使用原有管理员鉴权与权限限制：`GET/PUT` 读取/保存配置，`GET /events` 按 `ip/reason/category` 筛选，使用 `page/page_size` 分页（从第 1 页开始），返回 `items/total/page/page_size/pages`；超过末页时返回最后一页，空结果返回第 1 页，`DELETE /events` 清空，`GET /bans` 查看活动封禁，`POST /unban` 接收 `{ "network": "198.51.100.1/32" }`，`POST /check` 接收 `{ "ip": "198.51.100.1", "user_agent": "python-requests/2", "auth": true }`。这些敏感读取和操作进入管理员审计。

## 开关语义与仅中国访问

- 关闭并保存：本机之后的新请求直接旁路新模块，不检查 UA、国家、Redis 封禁，也不写新风控计数或事件。后台配置仍会刷新。原有登录防护、认证、注册配额和限流继续工作；原系统已有的 IP 封禁不会被关闭新模块清除。
- 请求在进入中间件时取得策略快照。在途请求和既有长连接不会被中断；已经进入认证处理的失败请求仍可能按旧快照完成记账。重新开启会继续使用未过期的执行模式封禁。观察与执行的动态封禁空间彼此独立。
- 允许国家填 `CN` 或点击「仅允许中国 CN」，检查白名单和管理员当前 IP 后保存。先保持观察模式确认归属结果，再取消观察。该快捷按钮只修改草稿，不会自动保存或启用功能。CN 不自动包含 HK、MO、TW，需要时分别加入。
- “实时”指保存返回后的本机新请求，无需重启；不是跨节点原子切换。其他节点轮询同步，失败时保留旧配置。`IP_RISK_DISABLED=true` 是启动环境变量，需要重启，且不关闭原系统防护。

## 独立审查与修复

已安排独立审查 agent `review_iprisk` 进行只读核查及交叉复查，确认 serverless 签名原始 IP 来自可信代理解析，验证机器入口的原有鉴权仍保留。修复了配置 IO 阻塞全站、冷配置故障 503、Redis 故障阻断业务与关闭入口、地区限制破坏机器回源、短封禁旧计数立即再封、应急模式后台丢失原配置视图等问题。新增确定性并发与故障回归，覆盖慢读/慢写、旧刷新覆盖保存、空闲节点同步、取消隔离及 Redis 黑洞预算。

## 验证方式与边界

- 合并或发布前运行后端单元测试、受影响包的 `go test -race`、前端关键 Vitest 套件、ESLint、类型检查和生产构建；实际结果及工具阻塞记录在对应 PR。
- 后端回归覆盖国家允许名单、关闭后的旁路、旧登录限流开关兼容、数据库慢读/慢写、并发保存、空闲节点同步、Redis 故障和取消隔离、自然解禁及应急配置读取。仅使用隔离 Redis/mock，不默认调用真实支付、邮件或付费模型。
- 前端回归验证仅中国快捷按钮只改草稿、保存与预览分离、事件筛选、解封/清理和错误恢复；中英文 locale 键保持同步。界面使用虚构数据检查桌面和 390px 手机布局，截图作为 PR 验收材料，不提交源码仓库。
- mock 与本地验证不能证明生产环境的稳定性。真实 GeoJS 网络、CDN 转发头、多实例同步和业务回调需在隔离部署环境继续联调。

参考：[OWASP 登录限速与认证防护](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[GeoJS 国家解析字段](https://www.geojs.io/docs/v1/endpoints/geo/)。

## 匿名 API 鉴权失败防护

新增独立、默认关闭的匿名 API 防护配置与临时封禁管理入口，详见 [匿名 API 防护](anonymous-api-guard.md)。此类 ban 仅在凭据明确失败后生效，不拒绝同 IP 的合法 key，且不与登录封禁/永久黑名单共用解除操作。
