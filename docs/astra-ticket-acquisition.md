# Astra 门票：快速复用与自采

> 历史实现记录：本文描述旧版门票采集与复用流程，仅供版本追溯，不作为当前部署或配置指南。新人请从[新人入门](新人入门.md)开始；协议配置和账号质量检测分别参阅 [Excel / BPS](excel-bps.md) 与[质量运维](account-quality-operations.md)。不要按本文启用旧开关或部署配套服务。

启用门票采集、目标长度为 780、模型包含 Astra，并开启网关借票时，快速复用和自采使用同一份账号门票库。已有开关均保留；升级不会自动开启采集或扩大账号范围。其他长度、关闭门票采集的独立网关路由模式沿用原行为。

## 两种获取方式

**快速复用**使用网关设置中的来源账号已经入库的有效 SSE 票，来源缺票时调用同一自采器补票，不维护另一套来源票库。目标始终使用自己的 OAuth 和 workspace：先带来源的完整 Cookie 对及 state 发一条短请求，必须取得不同的目标 state；再回带目标 state 和实际 Cookie 对续接。两次均完整结束、目标原票不再重签且 Cookie 对不变，才将目标的完整票入库。

来源 state 只用于启动验证，不会作为目标的有效票入库。目标保存的是自己的 state、Cookie 对、模型、协议、有效期、来源标记和出口／节点。Cookie 内的 gateway host 是路由描述，不是额外的认证凭据。

**自采**沿用目标账号自己寻找出口、取票、回带复验的流程。单号定向打票保留为明确的自采入口，串行和并行仍使用现有最大请求预算。后台自动补票先对配置为借票目标的账号尝试一次已入库来源，失败后可继续自采；两步共用本轮预算。账号／模型限流、明确拒绝、取消或持久化失败不会继续自采。

手动自采与按需快速复用持有采集互斥锁，后台 hunt 使用同一锁的读端及账号／模型 singleflight。已有有效目标票直接使用，不再额外跑借路由的两次探针。后台继续遵循主票／备用票和提前刷新规则，并非每轮给每个账号重新采票。

来源当前没有合格票时，网关准备会在 90 秒与共享请求预算内调用现有自采器；仍遵守来源的采集范围、跳过标记和冷却，无可用来源时才返回失败。网关“验证目标”在没有有效目标票时执行有界快速复用，已有目标票则复用当前准入结果。前端统一放在“打票全流程”的节点记忆与采集速度容器中，旧独立缓存不计入统一模式的就绪状态。

## 业务只使用一份完整材料

业务优先使用目标已经入库的有效票。确定 state、Cookie 对与出口后，网关层不能再将其中一个 Cookie 或出口替换为另一来源。即使借票来源后来轮换或过期，已建立的目标票仍由它自己的有效期与响应反馈决定是否可用。

快速复用形成的票和自采票都通过现有主票／standby 存储、身份绑定、响应失配失效和脱敏逻辑处理。应用重启后从账号记录恢复，不能只恢复一个“探针通过”布尔值。借票界面的目标就绪和自动账号调度读取这份票库；正常的自采票也能使借票目标就绪。

快速复用当前只为 SSE 建立目标票。WebSocket 必须已有同协议的有效目标票，不把 SSE 探针当作 WS 准入。已有 WS 完整票和出口不会再被网关 Cookie 覆盖或重复占用节点租约。

## 验证边界和费用

一次成功快速复用最多两次短模型请求，命中已入库目标票不发探针；后台的快速复用和自采都计入同一请求预算。失败探针也可能产生费用，不会重放已经发送的业务请求。源码测试使用离线 mock，不代表线上成功率、费用节省比例或长期稳定性已测量。

“完整续接通过”表示两次短响应结束、state 和 Cookie 连续性通过，不能独立证明解题质量。跨账号启动时来源 state 被换发，也不能直接判定目标降级。质量应另用有明确答案的题组判断；不能把正常来源的通过代替目标恢复。

已有实验显示不同降级目标的表现可以不同。这个改动统一材料生命周期与任务管理，没有承诺一张全局票能使所有账号恢复，也没有修改 780 票的 240 秒本地使用上限或把 Cookie 的声明有效期当作 state 寿命。

## 兼容和回滚

没有数据库迁移、配置字段或 API 必填参数变化。账号已有票的 JSON 结构增加可选 `acquisition` 和 `source_account_id`：新复用票记录 `reuse`，新自采票记录 `self`，旧数据缺字段仍按原规则校验。原值仍在受限票据字段中，账号导出继续剔除，不输出 Token、Cookie、state 或代理凭据。

旧二进制会忽略这两个可选字段，但会恢复旧的路由覆盖行为；这不是清除账号数据库或需要重建票库的回滚。关闭网关借票只关闭快速复用入口，已验收目标票仍可在门票采集开启时按原有效期使用。关闭采集开关后仍沿用既有独立路由模式。
