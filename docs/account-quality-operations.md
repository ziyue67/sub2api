# 降智运维

管理员侧边栏「质量运维」集中管理账户质量检测。每个账户可同时配置一条分组/调度规则和一条自动 BPS 规则，暂停只占用同类规则名额。可批量选择账户创建，也可多选已有规则批量编辑；单条规则仍可编辑、暂停、手动触发或删除。

## 多选编辑与窗口适配

- 账号规则卡片左侧复选框用于批量选择，点击账号名称仍用于筛选运营记录。搜索后可全选当前结果，切换搜索条件保留此前选择；清空已选会取消所有勾选。
- 点击「批量编辑」，勾选需要统一修改的检测模型、检测频率、检测配置、失败处理与目标分组、自动恢复或定时检测开关。未勾选的字段保留每条规则自己的值。初始输入来自第一条已选规则，检测配置包含检测方式、题目、参考答案、推理强度、检测次数和判题模型。
- 保存前刷新规则列表，合并每条规则的配置。逐条保存时显示处理进度；部分失败会保留失败项及错误信息，重试只处理剩余规则。此流程不是服务端原子批量事务。
- 桌面双栏使用可用宽度和剩余窗口高度，两个列表分别滚动；矮窗口收紧顶部区域。窄屏上下排列面板，手机端运营记录按卡片展示，编辑抽屉的保存按钮固定在底部。

## 配置

- 配置测试模型、题目、参考答案、推理强度、五段 Cron 和每轮 1–8 次测试。另外选择判题分组与判题模型，填写判题提示词；模型无固定默认值。
- 糖果题沿用账号的答题传输，不限于 OAuth 账号，API Key、Setup Token 等现有传输支持的账号类型也可使用。按账号路由检测时，显式配置的模型映射（含别名和通配符）可作为检测模型，即使上游 `/models` 未列出；未被映射覆盖的模型继续读取目录校验。可配置不保证上游实际可用，明确的运行时模型拒绝仍会使该模型跳过检测。状态探针、BPS 通道和自动透传仍按各自目录校验。
- 内置糖果题及预期答案 `21` 沿用 frontier PR #1 的约定；可改为自己的题目和答案。此检测是单题质量门槛，不是完整模型能力评估。预期答案只属于题目配置，判题模型不固定为 Luna。
- 由配置的模型比较回答与参考答案的语义，例如 `21个。` 可以与 `21` 等价。判题分组自动选择支持该模型的可调度账户，排除被测账户并占用并发槽；请求或输出解析失败时最多尝试 3 个账户。只有明确的 `incorrect` 结论触发失败动作；超时、鉴权错误、未完成响应、无可用判题账户和 `unknown` 均不触发账户变更，也不会恢复账户。
- 失败动作二选一：取消指定分组的账户归属（其他分组不变），或关闭账户调度（分组不变）。
- 自动恢复默认关闭。开启后，后续一整轮全部通过才尝试恢复。后台按账户 ID 测试，移出分组或关闭调度不妨碍复测。
- 服务每分钟扫描到期计划；「立即检测」进入下一次扫描，不直接在浏览器中调用模型。

## 随机推理题

在检测方式中选择「随机推理题」。保留测试模型、判题分组、判题模型与判题提示词，题目和参考答案由服务端在每轮执行时生成，无需手工填写。旧规则和糖果题不会自动切换。

- 首版包含路径计数与加权异或两个题族，运行时随机生成参数。每模型测试次数可设为1–8；批量样本轮换题族，同一轮各检测模型使用同一组题。
- 参考答案在本地由有界动态规划或穷举求出，不调用被测模型求答案，不向被测模型发送参考答案。题目生成失败时记录为无法判定，不发送测试请求，不触发失败动作。
- 判题沿用配置的分组和模型，选择支持模型的可用账号并排除被测账号；只发送参考答案和候选答案两个值，不发送题面。只有明确 `incorrect` 才触发失败动作。未配置判题器、请求失败、解析失败或 `unknown` 均不触发失败处置或自动恢复；多模型轮次同样遵守此边界。
- 每个实际题面、参考答案、题目标识、题族和生成器版本保存在管理员检测结果中，便于复核；可在运营记录详情展开本次题目。可复用规则和分组模板不保存生成实例，重启后下一轮继续生成新题。
- 使用 BPS 通道时仍只观察、不处置；5xx触发已选随机题规则时保留该题型及外部判题器，不回退固定糖果题。原有上游5xx保护与冷却机制不变。
- 开源的是生成器与本地求解程序，不发布运营使用的固定题库、实际题目/答案清单或私有测试记录。新版本可更新生成器与题族；不需要公共解密密码或密钥分发，生成器版本记录用于追溯。

随机参数减少固定题目与固定答案的硬编码适配，但上游仍能看到请求题面，公开生成规则也可被识别，不能保证抵御全部提示词注入或识别真实模型。两个题族不是完整能力评测；不同参数的区分度仍需实测，不能保证某个模型永远答错。不要仅凭一次失误认定账号降智。

该模式使用已有JSON配置和历史字段，无数据库结构迁移。旧二进制不识别 `random_reasoning`；降级前暂停或改回旧题型。混合版本滚动部署期间暂不启用新模式。

## 恢复与并发

数据库租约防止同一账户的智力检测计划同时执行。执行完毕重新校验计划版本、启用状态、租约，暂停或编辑期间产生的旧结果只记历史，不修改账户。

恢复只撤销该规则真正执行的变更，不开启原本已关闭调度的账户，不新增原本不存在的分组归属。分组恢复保留优先级和分组模型限制。账户更新时间或分组关系与隔离后快照不一致、账户非 active、分组已删除，均拒绝自动恢复；调度恢复也检查账户有效期。

手动改动后可能出现「恢复冲突」，应在账户页检查并手动处置。规则持有隔离记录期间不会重复覆盖人工调整；需重建隔离基线时，先手动处置账户，再删除并重新创建规则。暂停和删除规则均不会自动恢复账户；删除会清除该规则历史及恢复记录。

账户变更、恢复记录和调度缓存 outbox 事件在同一数据库事务内提交，包含已移出分组以使旧分组的调度缓存也得到刷新。历史最多每计划 200 条，页面默认保留 100 条，按现有定时任务清理超过 7 天的记录。请求响应只作文本展示。

## 运营记录

规则列表下方按轮次展示全局运营记录，包括检测时间、账户、处理状态、完成时间、规则目标分组及通过数/总数。恢复分组显示“已恢复原分组”。按游标加载更多，点击详情再加载该轮回答与每次判题理由、实际使用的模型及账户。表格的分组列是规则配置的目标分组，不冒充实际移除的完整分组差异。

- 迁移 `247_account_quality_ops.sql` 增加动作记录字段、恢复状态表和每账户质量规则唯一索引；`248_account_quality_judgment.sql` 增加判题结果和轮次标识。没有改写已有计划或账户。旧质量规则未配置判题器时仅记录不确定结果，需编辑规则选择判题模型和分组后才会自动处理账户。旧误判记录不会回写或据此自动恢复已移出的分组。

此功能提交不包含生产部署。真实模型请求会消耗对应账户额度；本地验证使用 mock 输入和隔离数据库。

## BPS 与分组规则共存

迁移 `254_quality_bps_coexist.sql` 将每账户唯一限制调整为按处置类型分别唯一，不修改已有规则或检测记录。账号编辑页和质量运维的新建/批量选择均允许为已有分组/调度规则的账号添加 BPS 规则，反向也可以；同类规则仍需编辑已有规则。

两类规则独立保存检测频率、连续次数、恢复快照与记录，同账号检测仍串行执行。BPS 规则默认每 30 分钟通过正常协议探测，不经过 BPS。开启 BPS 不直接加回分组；分组规则开启自动恢复后，需自己的检测通过才恢复原分组。糖果题可通过 BPS 检测，状态探针始终检测正常协议。

已有两类规则的数据不能直接恢复旧的每账户唯一索引；回退该约束前需先处理重复账号规则。

## 按模型隔离，全部降智才移出分组

答题检测新增可选动作 `isolate_models`，旧规则不会自动切换。选择检测模型和目标分组，按需开启自动恢复；无需另填冷却模型名单。账号级状态探针不能使用此策略。

| 本轮模型结果 | 模型处置 | 所选分组 |
| --- | --- | --- |
| Sol 答错、Astra 通过 | 仅隔离 Sol | 保留 |
| Sol、Astra 均明确答错 | 分别隔离两个模型 | 移除本规则选定且原本存在的归属 |
| 全部隔离后，Astra 通过、Sol 仍答错或未知 | 自动恢复开启时仅恢复 Astra | 加回本规则移出的原分组 |
| 所有模型均通过 | 自动恢复开启时分别恢复 | 恢复本规则移出的原分组 |
| 含超时、判题未知、未检测或跳过 | 不新增对应模型隔离，也不解除其原有隔离 | 不因这些结果新增整组移除 |

“全部降智”要求本轮所有检测模型都有明确的失败结论，不使用跨轮次的旧结果补齐；账号内映射至同一上游模型的别名共用隔离，同轮答错或未知不会被另一个通过的别名解除。隔离针对该账号的所有分组，未参与检测的其他模型不受影响。恢复模型只撤销本规则持有的隔离，不清除原生 429 冷却、手工限制或其他运行状态；也不会打开原本关闭的账号调度。此策略不改变账号并发。

隔离保存在账号 `extra.quality_model_isolation`，与原生 `model_rate_limits` 分开，没有自动过期时间。重启、暂停、原生冷却清理均不会自行放行；关闭自动恢复时，通过仅记录结果。后台继续按账号 ID 直接复测，不受自身调度隔离或分组移除影响。

本策略和旧“仅冷却指定模型”共用模型结果归并、别名处理、隔离/恢复及历史动作生成函数；与旧“移出指定分组”共用分组变更和 outbox 事件函数。组合规则仅负责“何时调用这些能力”，不另外实现一套调度器。

模型、分组快照和缓存事件在同一事务提交，旧租约结果不能处置账号。至少一个模型明确通过且开启自动恢复时，恢复原有分组的优先级、创建时间及模型限制；不新增原本没有的归属。发现目标分组已删除、人工重建归属、隔离记录被其他操作替换或模型映射改变时停止自动恢复，整轮回滚并显示冲突。

持有本策略的隔离记录时，允许暂停、修改检测计划和切换自动恢复；修改动作、检测模型、目标分组或删除规则之前，必须先恢复本规则的处置，避免失去持久隔离的恢复依据。旧规则已经移出分组或关闭调度时，保存切换到本策略会自动恢复本规则的旧处置，并清理旧恢复记录，无需先复测通过，也不要求开启自动恢复。恢复和策略保存处于同一事务；账号状态异常、调度恢复时账号已过期、原分组已删除或分组归属被人工重建时，提示具体冲突并撤销本次全部修改。只恢复旧规则实际移除的分组及其优先级、创建时间和模型限制，不新增原本没有的分组归属，不改动并发、模型冷却或独立 BPS 规则。新策略从后续检测结果开始处置模型，不使用历史检测结果生成隔离。

无需数据库结构迁移。旧二进制不识别新隔离键和新动作，不能保证调度隔离；降级前须恢复全部此类规则的处置，并改回旧动作或删除规则。混合版本滚动部署期间也不能保证旧实例执行模型隔离，应在实例全部升级后启用新策略。
