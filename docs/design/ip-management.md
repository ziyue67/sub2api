# IP 管理：Mihomo 订阅管理与页面结构

日期：2026-09-27。基线：production dcf523bf1。

## 现状与目标

用户提供的 IP 管理截图只有静态代理列表与 HTTP/HTTPS/SOCKS5/SOCKS5H 协议筛选；Mihomo 的订阅、动态代理、节点和地区规则嵌在系统设置的打票代理区域。现有订阅 API 只返回数量，不能逐条更新、停用或删除。

本次将代理资源管理归入左侧 IP 管理。协议是连接属性，不用协议下拉菜单承载订阅管理入口。系统设置保留打票出口选择、就绪校验及 IP 管理跳转。

## 信息架构

| 页签 | 主要内容 | 操作 |
| --- | --- | --- |
| 代理列表 | 现有静态代理/IP 池 | 原有搜索、协议、状态、测试、导入导出 |
| 订阅 | 名称、启用状态、节点数、最后成功更新时间 | 添加、改名、换地址、更新、启停、移除、批量操作 |
| 动态代理 | 独立动态节点表格、延迟与质量 | 追加/替换导入、逐条移除、搜索和分页、测试连接、质量检测 |
| 节点 | 汇总节点、来源、状态、地区、延迟与质量 | 搜索、来源/状态筛选、测试连接、质量检测、网络/地区检测、停用/恢复 |
| 内核与规则 | 内核安装/启动、地区准入、用后移出 | 每项操作独立提交 |

Mihomo 管理页上方保留紧凑的运行状态及本地出口；后端有 Warm IP pool 字段时展示，旧版不伪造计数。千级节点每页 50 条，避免把所有节点和国家选项挤进打票配置卡片。

## 交互原则

- 沿用现有白底卡片、浅色背景、primary 色、圆角、DataTable、BaseDialog 与 ConfirmDialog，不新增 UI 框架。
- 创建/编辑表单放在对话框，列表保持可扫描；导入格式说明按需展开。
- 添加订阅默认追加，动态代理默认追加。替换动态代理须明确选择并确认，不隐式删除机场订阅。
- 订阅移除显示影响说明；不同来源共享的节点保留。删完最后一个来源后拒绝代理流量，不能继续使用旧节点或回退直连。
- 批量按钮只在选中订阅后展示；请求按后端管理锁逐条执行，失败即停。
- 请求被接收不等于操作成功。前端等到 busy 结束并检查 error 后才清空草稿、显示成功。
- 订阅 URL 不回显，路径/query 都可能含 token。列表用可编辑名称及稳定摘要 ID；旧数据首次成功更新时建立来源缓存。
- 动态代理与节点页签的测试连接、质量检测与静态代理列表一致：逐条按钮加工具栏批量按钮；勾选节点时批量检测所选节点，否则检测当前筛选的全部节点。结果显示在延迟列，质量报告复用静态代理列表的对话框。检测经独立内核进行，不改变节点状态；原“检测”按钮仍会按结果标记失败或恢复节点。
- 管理入口迁移不改业务选路、打票设置或账号代理绑定。

## 验收

验证逐条更新、改名、启停、移除、动态代理共存、共享节点保留、最后来源移除、旧配置兼容、敏感字段脱敏及失败回滚。前端验证异步失败保留草稿、移除确认、千级节点分页、来源筛选与打票设置跳转。所有运行测试使用 mock/本地 HTTP，不访问真实订阅或修改生产代理。


## 后端依赖与合入顺序

#142 的目标分支为 #143 的 feat/mihomo-management-backend。通用来源管理、订阅下载模式、管理员路由及其 Go 回归均归 #143；本 PR 相对该基线只包含前端和接入说明。

前端沿用 GET /admin/system/mihomo、POST /admin/system/mihomo，下载模式独立调用 PUT /admin/system/mihomo/download-mode，正文示例为 {"mode":"direct"}，可选值为 auto / proxy / direct。接口行为见 mihomo-backend-api.md，路径中的 /api/v1 由 API client 添加。

先审查并合入 #143，再将 #142 的目标分支改回 production，核对前端差异后合入。原提交历史保留，通过追加整合提交收敛最终文件差异，不重写远端分支历史。

BPS warm pool、订阅优先策略和转发逻辑继续由 #133 维护。本页面兼容可选的 bps_warm_pool / bps_ip_warm_pool 状态：#143 未提供这些字段时隐藏对应卡片，不伪造计数、不发起预热；服务提供字段时直接显示就绪数与来源计数。

原 73f560495 中的 BPS 实现及其回归保留在该提交历史中，包括订阅候选被同批取消后的优先级修正；本次将它们从前端最终差异移除，没有修改或推送 #133。后续整合 BPS 时需核对该修正与 #133 的对应实现。

## 验证边界

接口回归使用本地 HTTP/代理 mock，前端使用模拟管理员响应。验证范围为来源管理、下载模式、异步失败保留草稿、分页筛选，以及预热字段存在或缺失时的兼容显示；不以这些测试推断真实供应商连通性或模型成功率。

后端依赖和可选扩展记录在 ip-management-backend-sources.json；没有数据库迁移或生产配置变更。
