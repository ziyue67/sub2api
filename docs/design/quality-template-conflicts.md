# 质量模板切换与旧归属对账

当质量规则持有模型/分组隔离时，替换其范围不能丢弃恢复归属。当前保存返回普通400，删除返回500；管理员也缺少预览并解决缺失隔离项的入口。本变更将这些操作放在同一明确流程：导入配置草稿 → 比较范围和当前归属 → 明确解决冲突 → 再保存。

## 不变条件

- 不删除scope/ownership守卫，不根据答题通过、分组已存在或模型可用猜测已恢复。
- 预览和确认只输出业务字段、model/group ID、存在性/归属枚举与摘要，不输出账号凭据、prompt、响应、任意Extra或原始限制JSON。
- 对账不更新账号、模型限制、分组、并发、检测开关、预算或冷却，不执行检测。它不是解禁。
- 仍与本规则记录完全匹配的限制继续受管，不因一个冲突项被清理而清空整个state。
- 运行中旧round仍按原版本成为stale_run；对账确认使用规则、账号和完整ownership状态fence，锁内重新预览验证，防止旧确认覆盖并发变更。

## API与交互方案

- update/delete对隔离范围冲突返回枚举HTTP409，保留原普通验证错误。
- 管理员GET规则ownership预览，显示已保存模型/组范围、当前/expected业务字段、不可丢弃项以及可放弃的旧归属。
- 管理员显式POST确认，必须带预览fence和确认标记。事务按plan→account→state锁序读取，重新计算同一预览；版本、真实限制或state任意变化返回409，零写入。
- 确认可放弃已不存在或已由其他规则/管理员持有的旧模型归属；仍启用的规则之后真实失败可以重新施加当前缺失的模型限制，但不能覆盖外部现存项。该确认不是永久豁免。只处理旧模型归属，不覆盖或删除真实限制。匹配项继续管理。当前标记仍指向本规则但内容变化时默认保留并明确阻塞，不以reason字符串推断完整所有权。
- 不做部分scope迁移。存在仍受管项时，界面保留用户草稿，说明需要先正常解决原范围；不能把HTTP409改善宣传成任意换模板已完成。
- preset下拉、点击应用草稿、保存规则是不同状态；规则名称保留，不当作preset绑定。复制规则和主动分组模板保持原有语义。

## 待审边界

同一规则标记但限制内容变化时，是否需要额外的“显式认领当前项作为新基线”操作，需单独确认设计；本PR初始方案不自动认领、不自动放弃。若确认后仍有真实受管条目，继续保留scope守卫，不偷偷移除限制来完成切换。

## 验证计划

远端CI覆盖：update/delete 409；相同scope允许保存；草稿不丢失；预览不泄露任意JSON；缺失/其他owner项目对账；匹配项目保留；同标记改动保留；plan/account/state变化fence拒绝；运行round不能覆写对账后的state；并发重复确认幂等或明确409。原回归断言保留。

本机只运行静态AST/格式/diff检查；动态后端、前端、集成和UI截图通过远端CI执行。没有生产操作。

## 分组对账边界

分组快照仅预览，当前不允许通过此入口放弃。若保留原检测target却放弃已由人工重建的组成员归属，下一次失败可能再次删除该成员；这需要单独的scope迁移/暂停动作设计。本PR不猜测该产品取舍，不以分组存在释放模型或组归属。模型对账有后续失败轮的外部owner保护。
