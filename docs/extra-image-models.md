# API Key 上游的额外生图模型

OpenAI API Key 账号可以显式放行内置模型家族以外的图片生成模型，例如 `nai-diffusion-4-5-full`。入口：管理员「账号管理」→ 添加或编辑 OpenAI / API Key 账号 →「额外生图模型（API Key）」。

- **精确模型 ID**：填写完整名称，例如 `nai-diffusion-4-5-full` 或对外别名 `my-nai`。
- **模型前缀**：填写字面前缀，例如 `nai-diffusion-`；不需要 `*`。精确匹配和前缀匹配均区分大小写。
- 每行一个，也可以用英文逗号分隔。两份名单默认空，清空并保存即可撤销授权。空条目不会匹配所有模型。
- 分组仍需开启「允许生图」，账号仍需满足现有模型映射、分组模型限制和可调度条件。额外生图名单只声明端点能力，不替代这些限制。

配置保存在现有账号 `extra` JSON 中，无数据库迁移。使用管理 API 时合并其他已有 `extra` 字段，不要覆盖无关设置：

```json
{
  "extra_image_models": ["my-nai"],
  "extra_image_model_prefixes": ["nai-diffusion-"]
}
```

请求原名、渠道映射目标、账号映射后的上游 ID，必须分别命中内置生图家族或**同一个账号**的额外名单。合成路由引入第三方模型时，对外原始别名也必须放行。只允许 `my-nai`、未允许映射目标 `nai-diffusion-4-5-full` 会在本地拒绝，返回 400，不发送生成请求。不同账号的名单不能拼接成一份授权。

```json
{
  "model": "nai-diffusion-4-5-full",
  "prompt": "a red circle",
  "n": 1,
  "size": "1024x1024"
}
```

向本站 `POST /v1/images/generations` 发送以上正文。模型名保留为目标 ID，正文只按现有映射规则替换 `model`，其他字段保持透传；不会改成 `gpt-image-2` 或转换成 Responses。未知扩展参数仍由上游决定是否支持。

上游成功 JSON 中的 `data[].b64_json` 可直接作为图片结果，即使 `url` 是空字符串、响应头为 `binary/octet-stream`。沿用已有响应头过滤行为：启用过滤时返回 JSON Content-Type，关闭时可以保留上游类型。

## 范围与后台测试

- 仅 OpenAI API Key 账号的 `images/generations` 生效。OAuth / Setup Token 不接受此名单作为图片工具授权，GPT 官方模型识别、Responses 工具转换和官方定价判定不变。
- `/v1/images/generations/async` 复用相同授权；仍需配置并启用现有异步图片存储功能。流式请求不能提交为异步任务。
- 本次不放行额外模型的 `/v1/images/edits` 或其异步入口，也不转换第三方编辑请求格式。
- 后台账号测试选择已放行模型（包括授权完整的账号映射别名）时，走上游 `/v1/images/generations`。模型选择列表仍由上游目录与现有账号映射规则决定，前缀本身不会凭空生成模型目录。

## 价格与运行影响

名单不提供价格。请单独配置分组或渠道的生图价格；沿用现有模型价格解析与图片计费路径，不套用 `gpt-image-2` 官方价格。若没有显式生图价格且价格目录不认识该模型，现有兜底为 1K **$0.134/张**、2K 为其 1.5 倍、4K 为其 2 倍，再应用倍率。

自定义模型校验增加当前分组内的账号授权读取，不探测上游，不产生额外上游请求。调度和最终转发继续校验所选账号，保留原有并发、重试及计费流程。授权存储不可用返回 503，和模型未获授权的 400 区分。默认模式仅检查当前分组（未绑定分组时仅检查无分组账号），simple mode 沿用全平台账号池。

回滚二进制无需回滚数据库。旧版本保留但忽略新增 `extra` 字段，第三方模型将恢复为本地拒绝；重新升级后配置仍可能存在。
