# Responses 流的心跳与终态边界

普通 `/v1/responses` 流式请求复用 `gateway.stream_keepalive_interval`。默认 10 秒，设为 0 时禁用；无新增配置或数据库迁移。

## 覆盖阶段

在 OpenAI 原生与透传 HTTP 请求发送正文、等待响应头期间，按上述间隔向客户端发送 SSE 注释心跳。请求处理在接管响应之前停止并同步心跳 writer，避免注释插入正在写出的事件。响应体阶段继续由已有 SSE reader 管理心跳。

注释不属于模型输出，不结束上游首输出/上传预算，不新增重试、不重新执行工具调用，也不会仅因发过心跳就禁用原有的安全切号。各账号尝试的心跳字节累加后仍从语义输出判定中排除。

## 错误与取消

- 未发出心跳时，快速错误保留原 JSON 和 HTTP 状态码。
- 心跳已经把响应提交为 HTTP 200 后，后续 JSON/Data 错误转换为合法 `response.failed`，保留净化后的 message、type、code 和 param；业务状态另记入 Ops。不会向 SSE 尾部混入普通 JSON，或伪造成功终态。
- 心跳 write/flush 失败后不再向客户端写入，也不启动新的账号尝试；已发送的上游请求继续按现有机制排水、收集已观测用量。
- 客户端取消和请求现有超时预算保持；心跳不表示上游有语义进展。

## 证据边界

`terminal` 表示解析到的上游终态；`terminal_flushed` / `terminal_output_flush` 只表示网关本机终态 write/flush 成功，不证明外层代理或客户端已收到、解析成功。`body_complete` 表示入站请求正文读完。

心跳覆盖长首响应空窗，但不能修复上游忙碌、加密上下文来源不兼容或外层网络故障。客户端可能按 SSE 事件而不是任意字节计 idle；是否消除具体客户端重连，仍需部署后关联请求和客户端日志验收。
