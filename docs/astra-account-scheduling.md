# Astra 号池分组调度

开启号池调度、选择「自动加入 / 移出指定分组」并保存后，目标账号探针通过且路由有效时，会自动加入所有勾选分组，包括此前从未加入的分组。无需先手动把账号放进分组。失败、过期、无有效路由或账号不再符合准入条件时，移出所选分组；其他分组不受影响。

后台每秒读取已有探针状态，不额外发送模型请求。稳定状态不会反复改写成员关系、更新时间或生成变更记录。实际加入、移出通过原有调度缓存失效流程同步，并进入当前实例的最近三条记录；实例重启清空这些展示记录，但数据库中的接管记录保留。

已有成员关系恢复时保留优先级、创建时间和分组内模型限制。首次自动加入使用通常的成员默认值：优先级 50、不额外限制模型。不会更改账号整体调度开关或其他模型设置。

接管记录分别保存每个所选分组的初始关系与上次生效关系。人工增删成员、修改优先级或模型限制后，与接管记录冲突时拒绝覆盖，整个账号的本轮变更回滚。修改其他分组或账号名称不会导致分组恢复冲突。

切换模式或所选分组时，先撤销旧范围内的接管动作：恢复本功能移出的原有关系，移除本功能新加的关系，再应用新选择。关闭号池调度开关只停止同步并保留当前状态。

旧版 `removed` 接管记录在首次同步时转换为同一 JSON 状态中的成员快照，保留原成员属性，不需要数据库结构迁移。部署后，已有分组模式也会按新规则自动加入。旧二进制不理解新增的 `memberships` 字段，因此回退前应通过新版切换到其他模式撤销分组接管，并确认没有冲突；仅关闭开关不会撤销成员关系。账号与模型模式的恢复规则保持不变。
