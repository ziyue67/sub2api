## v0.2.10 增量（本次新增）

- **Claude 原生重置额度（reset credits）**：新增 `claude_reset_credits.go` 与 `claude_reset_handler.go`，账号页可按需查询 Claude 侧重置额度状态并展示在账号单元格（`ClaudeResetCreditsCell.vue`），新增管理端路由 `GET /accounts/:id/claude/reset-credits`
- **风控用户白名单**：新增 `cyber_policy_user_allowlist` 设置项与 `cyber_policy_allowlist.go`，白名单用户（按用户 ID / 邮箱模糊搜索）命中风控时只记日志（log-only），不落账号封禁与会话屏蔽；管理端设置页新增白名单选择器，HTTP 与 WebSocket 准入对白名单用户跳过既有会话屏蔽查询
- **Claude Sonnet 5.5 支持**：新增模型与计费识别，并保留 Opus 5.5 thinking 相关行为
- **分组「仅 Claude Code 客户端」**：仅允许 Claude Code 客户端的分组会隐藏不支持的客户端入口
- **模型白名单与映射冲突修复**：账号级白名单不再覆盖模型映射，避免「白名单模型映射冲突」把可用模型误拒
- **网关路由归属修正**：复合（composite）模型路由在传统调度与 WebSocket 别名场景下按账号归属解析，避免歧义路由把请求交给非归属账号；修正晚到的缓存输入扣减
- **流式用量归一化**：Chat 流式转发的 usage 现在会随响应归一化并上报，修复流式请求用量缺失
- **Anthropic 工具名重写**：工具名重写改为单次 body pass，避免重复改写
- **Antigravity 兼容流保活**：首个内容块到达前的兼容流保持存活（`fix(antigravity): keep compat streams alive before first content`）
- **Codex 模型目录**：OpenAI 分组不再下发 Codex 模型目录（`fix: omit Codex model catalog for OpenAI groups`）
- **看板用量趋势切换**：管理端看板支持在 tokens 与消费金额（actual_cost）之间切换近期用量趋势
- **依赖清理**：移除初始化阶段写入的已废弃限流默认值

## Fork 适配与冲突处理

- `backend/cmd/server/VERSION`：跟随上游写入 `0.2.10`。代价是该版本在语义化比较中小于 `0.2.91`（应用内检查更新可能判为更旧）
- **cyber 设置项（union）**：保留 Fork 的 `CyberSessionIdentityStrictEnabled`（设置键、解析默认值、DTO、请求体、`cachedCyberSessionBlockRuntime.strict`、严格身份门控准入），并新增上游的 `CyberPolicyUserAllowlist`（设置键、解析默认值、设置视图、DTO、请求体、`allowlistedUsers` 缓存、log-only 记录）。合并产生的重复 `cacheTTL` 声明已去除；`enabled` 读取失败时保留 Fork 的 fail-closed 提前返回，并沿用「刷新失败时保留上一次白名单」的上游语义
- `backend/internal/handler/openai_gateway_handler.go`：保留 Fork 的 turn 准入、分组禁用模型与严格 cyber 身份机制，并在所有屏蔽点接入上游的 `cyberPolicyLogOnly` 放行。WebSocket 首帧改为显式解析复合路由（`wsRouteModel` + `WithCompositeRouteDecision`）取代 `ensureCompositeTargetPlatform`；Fork 的禁用模型校验保持在前
- `backend/internal/handler/openai_cyber_allowlist.go`：保留上游新增文件与白名单（log-only）语义，但 `findBlockedCyberSessionForAPIKey` 改为基于本 Fork 的类型化会话身份查询（`service.ResolveCyberSessionIdentity`）：上游的 `buildCyberSessionBlockWritePlan` / `findBlockedCyberSessionKey` 依赖本 Fork 已删除的 `openai_cyber_transcript.go`（本 Fork 采用严格身份门控，不引入 transcript 相似度键）
- `backend/internal/service/openai_ws_forwarder_ingress.go`：上游把准入可见载荷改名为 `rawForHash` 并单独保留 `clientWindowID`；两侧字段都保留，`hooks.BeforeRequest` 传 `rawForHash`（准入需看到映射前的客户端模型），同时保留 Fork 的 `invalidateOpenAIWSTurnStateAfterAdmissionFailureForRequest` 失效处理
- **设置管线**：看板 handler 保留 Fork 的 `parseTimeRange` 标签输出并新增上游的 `metric` 选择；管理端 settings 请求体 / 响应体与 `systemSettingsResponseData` 同时携带白名单与严格身份字段
- **依赖注入**：`routes/admin.go`、`handler/wire.go`、`cmd/server/wire_gen.go` 保留 Fork 的代理车道、openai-reauth、请求采集、token-guard 与 Excel / BPS 接线，并额外接入上游的 `ClaudeResetCreditService` 与 `claude/reset-credits` 路由
- **测试**：`openai_account_scheduler_test.go` 并集两侧新增用例，并按 Fork 的 `getOpenAIAccountScheduler(ctx, priority)` 签名调用；`openai_ws_v2_passthrough_cyber_test.go` 保留 Fork 的 `WithOptions` harness，上游的变参构造器作为其薄封装；`openai_cyber_allowlist_test.go` 改用 Fork 的显式屏蔽键断言（无 transcript 键）；`EditAccountModal.spec.ts`、`AccountStatusIndicator.spec.ts` 取两侧并集
- **i18n**：保留 Fork 更严格的 `cyberSessionBlockHint` 文案（描述本 Fork 的严格身份语义），并补入上游的白名单文案
