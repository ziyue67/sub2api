## v2.8.20 增量（本次新增）

- **BPS 429 按账号冷却与换号重试**（#161，Fixes #146）：Excel BPS 上游返回 429（`basispoints_rate_limited`）时，主请求、原生附件上传与 `invalid_encrypted_content` 重试在写出任何内容前返回 `UpstreamFailoverError`，复用调度层既有的账号排除、切换预算与客户端断开保护（客户端已断开按取消处理，不再切换）；全部候选失败后返回 429、`basispoints_rate_limited` 与校验过的 `Retry-After`，上游正文不外泄。触发 429 的账号进入进程内 BPS 专用冷却：优先用 `Retry-After`，否则用「429 默认回避」设置，范围 1–7200 秒，并发写入不缩短更长的冷却；冷却只对该账号设为走 BPS 的模型生效，不写 Codex 用量快照、限流重置时间或账号全局封禁，也不计入调度失败率。三种选号路径在无可用账号时记录 `excel_bps_rate_limited`，新请求得到 429 而不是 503
- **账号质量规则选择性批量编辑**（#163）：新增 `buildQualityRulePatch`，按「模型 / 计划 / 测试 / 动作 / 恢复 / 启用」逐字段把草稿合并进每条规则自己的 `pelican_config`（不再整体复刻首条规则），并新增响应式质量工作区、校验提示与配套中英文案
- **OpenAI 初始 2FA 登录导入**（#164）：新增 `openai_two_fa_login.go`，用邮箱 / 密码 / 2FA 密钥显式登录并把凭据保留在有界短生命周期内存中（最多 32 个任务、25 分钟超时、30 分钟过期），登录成功前不建账号、不改动凭证守护配置；新增 token-guard `two-fa-login` 的 POST / GET / DELETE 接口（审计日志对该路由整块省略请求体），账号弹窗与 `OpenAITwoFAImport` 组件接入；codex session 导入新增 `skip_existing` 跳过已存在账号
- **顶栏响应式**（#163）：`AppHeader` 左侧改为 `min-w-0` + `truncate`，长标题 / 描述不再把右侧操作区挤出可视区
- **文档与协作**（#160）：贡献者按已合并 PR 数量排序并补齐作者；本 Fork 的 `README.md` 为独立版式，未采用该节（冲突处保留 Fork 版式与 `VERSION`）
