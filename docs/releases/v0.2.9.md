## v0.2.9 增量（本次新增）

- **分组模型白名单支持任意位置通配**（#7595）：`*` 可出现在白名单的任意一段，匹配改为锚定且大小写不敏感（`groupAllowlistPatternMatches`），列表回显按来源模式展开通配项。原先「通配只能在末尾」的校验、对应 i18n 文案与 `endsWith('*')` 徽标判定一并移除；末尾通配的既有语义不变
- **客户端断开统一标记 499**（#7609）：客户端取消 / 断流在响应尚未提交时统一标记 `499`，不再补写成 `502` 或被归类为「200 上游错误」；OpenAI 传输错误路径会先识别 `isClientCanceledTransportError` 并提前返回（不记 Ops 错误、不触发换号、不摘除账号）
- **Codex WebSocket 上下文换代续链**（#7615）：上下文窗口换代时断开原 WS 链路并重新建链，避免旧链上下文被错误复用
- **OpenAI 透传账号补充模型发现**（#7526）：透传（passthrough）账号不再隐藏已映射模型，而是以「补充」方式参与模型发现
- **OpenCode Zen 推理占位**（#7562）：为 OpenCode Zen / Go 的 DeepSeek 上游注入 reasoning 占位内容
- **beta 能力透传**（#7638 / #7617）：保留客户端显式请求的 Anthropic structured outputs beta 与 Responses multi-agent beta
- **OpenAI 兼容桥修复**（#7538 等）：关闭 thinking 时不再强行注入推理；转换后的 role item 标记为 message、`content_block_start` 保留工具参数、末条输出消息为空时回退流式文本、GPT-5 起统一按推理模型处理
- **Antigravity 韧性**（#7607 等）：`MALFORMED_FUNCTION_CALL` 导致的空流触发 failover 重试；仅含 Signature 的事件不再算作「有意义数据」；工具 schema 保留 `string const` 约束；chat PDF 附件按 Gemini `inlineData` 转发
- **额度自动重置与暂停**（#7555 等）：已确认无额度的账号停止重复查询并对查询失败退避；额度暂停保留到「已知的将来重置时间」；调度快照保留 auto reset-credit 字段
- **计费与定价**：渠道价未设置图片单价时保留目录价（#7573）、账号统计计费遵循长上下文门槛、识别 OpenRouter 的 Claude Opus 5.5 别名、Free Fast 无定价时仍保留零成本用量日志、模型广场视频倍率独立生效
- **用量探针与搜索回退**：探测模型缺失时 Responses 支持状态保持「未知」（#7571）；alpha 搜索回退必须成功完成才计费（#7572）
- **ccswitch**：修复用量查询重复 `/v1/v1/usage` 路径；保留 Codex provider 的根端点
- **部署与界面**：`docker-compose` 的 redis `command` 改写为 exec 列表形式（#7610）；初始化不再写入已废弃的限流默认值；空闲用量窗口在已知重置时间时显示倒计时；Windows 下 Codex 模型目录改用 `~/`；分组弹窗清理监听与待处理搜索

- `backend/cmd/server/VERSION`：本次**跟随上游**写入 `0.2.9`。前两个版本使用 Fork 的 `0.2.81` 式编号（`0.2.8.1`），本次上游追平到 `v0.2.9`，而 `v0.2.9` 标签在本 Fork 未被占用，故直接采用上游版本号；代价是该版本在语义化比较中小于 `0.2.81`（应用内检查更新可能判为更旧）
- `backend/internal/service/group_model_allowlist.go`：两侧融合。保留 Fork 的 `supplementUnmappedOpenAIModels(groupID)` 签名与分组白名单优先判定（账号级分组限制仍然生效），并接入上游的透传分支（透传账号忽略 `model_mapping`，按未映射处理）；通配语义采用上游实现

- `backend/internal/service/openai_gateway_deepseek_chat_reasoning_test.go`：保留 Fork 的「出站模型驱动」用例，把上游的 OpenCode Zen / Go 用例移植到合并后的谓词上，并保留「非 DeepSeek 出站模型 + 第三方 host」的字节一致性对照
