## 上游增量（`b8dece900`..`3f1a2ea0a`，v0.2.14）

### 安全

- **易支付回调签名复用漏洞（#7881 / `d1aac6b98`）**：订单创建签名（用户在 `submit.php` 弹窗 URL 中可见）对 `return_url` 等字段签名时不做转义，
  客户端可在 `return_url` 末尾夹带 `&trade_status=TRADE_SUCCESS`，使订单创建签名与「支付成功」通知签名逐字节相同，
  从而把已签名 URL 当作伪造回调重放，**无需商户密钥即可绕过支付校验**。修复分两层：
  1. `CanonicalizeReturnURL` 丢弃客户端提交的全部 query 参数（`buildPaymentReturnURL` 会自行附加签名字段）；
  2. `VerifyNotification` 对参数做白名单校验，任何不在真实异步通知集合内的参数一律拒绝。
  白名单外键（`return_url`、`notify_url`、`cid`、`device`、`clientip` 等）在回调中一律 fail-closed；
  被误拒的真实已付款订单仍可由上游 `QueryOrder` 对账路径恢复。
  回归测试覆盖伪造签名复用、订单 URL 重放、未知参数、成功通知缺少 `trade_no` 等场景。
- **全新安装不再预置可猜测的管理员口令（#7850 / `6e315616e`）**：全新部署曾使用可猜测的默认管理员凭据。
  现改为由部署脚本生成随机初始密码并在安装结束时一次性展示，`deploy/` 下各 compose 与脚本同步更新。

### 修复与依赖

- **远端 Codex 目录启用 API Key 模型发现（#7851 / `bbba01dae`）**：`UseKeyModal` 在「远端模型目录」模式下生成的 Codex 配置补上
  `api_key_model_discovery = true`，使 API Key 模式能够发现远端目录中的模型。
- **前端依赖安全审计（`0f9d460dc`）**：Vue 升级到 `^3.5.43`，`source-map-js` 覆盖提升为 `>=1.2.2`；`audit-exceptions.yml` 中 xlsx 例外说明改为
  「仅写入、无解析路径」并顺延有效期。
