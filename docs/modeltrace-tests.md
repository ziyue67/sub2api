# ModelTrace 手动指纹测试

入口：管理员账号管理 → 账号的智商测试 → **ModelTrace 指纹**。

选择请求模型和可选的思考强度，点击“开始三题指纹测试”。后端生成三条随机题目，每条要求语言模型直接输出 292–332 个 1–355 的整数；三条题目分别请求同一个账号，不携带上一题对话。按现有账号映射处理模型别名，不通过调度器换号。不自动补题或因归因不一致重试，每轮最多三题；请求消耗上游额度，不另用模型当裁判。

支持原生 OpenAI OAuth/API Key（Responses 或 Chat Completions）及 Anthropic OAuth/API Key（Messages）文本路径。首版不支持 Excel/BPS、Prism、Agent Identity、影子账号、Bedrock/Vertex 服务账号及其他平台；后端在开始前及每题执行前核对实际通道。模型列表允许手动输入及配置别名，指纹候选范围以结果中的内置库列表为准。

普通 API Key 请求不附加现有鹈鹕/糖果的 HTML 或整数答案交付约定，也不附加 Codex / Claude Code 系统提示词。OAuth 保留原测试路径所需的指令，并在各题记录中披露。Claude Code 系统提示词尤其可能干扰指纹；思考强度、上游隐藏系统提示词或采样设置也可能造成分布偏移。

每题保留题目、原始回答、实际映射模型、协议与系统提示词类型、开始时间和耗时。正常结束且可解析数字数不少于 `max(80, ceil(要求数量 × 0.55))` 才参与归因。拒答、数字不足、截断、提前 EOF、超时及上游错误不计入。每题超时 240 秒，输出采集最多 4 MiB SSE，结果文本最多 64 KiB；超限不计入。三题按顺序执行；每个服务进程同一账号最多一轮 ModelTrace，多副本间不提供分布式互斥，也不额外锁住普通业务请求。

结果展示模型候选与家族概率、每题归因、有效样本数及单题预测分歧。仅 1–2 题有效时显示初步归因，无有效回答时显示无法归因。合并结果按有效回答逐题评分后取均值，并采用实际有效样本数对应的校准。单题结果使用一题校准，因此与合并概率不必相同。当前库未收录的模型仍会被分配到某个现有候选，最高概率不是身份或降智的证明。结果不自动隔离、封禁或恢复账号；现有请求路径对认证失败、限流及配额头的处理继续生效。

测试使用管理端认证和服务端已有账号凭据，不接受外部 API Key、任意 Base URL 或自填答案。指纹库和评分均在本机，题目与回答不会发送给 ModelTrace。前端仅在当前浏览器按账号保留最近五轮完成的测试，包含题目、回答、请求模型、思考参数和指纹库 SHA/校验值；可清空历史。不新增数据库表，取消或连接提前结束的整轮不写入浏览器历史。存储空间不足时当前结果仍可查看，提示历史保存失败。

服务端管理端接口：`POST /api/v1/admin/accounts/:id/modeltrace-test`，请求示例（虚构模型别名）：

```json
{"model_id":"public-model","reasoning_effort":""}
```

校验失败在 SSE 开始前返回普通 HTTP 错误；已运行时返回 409。流事件依次为 `modeltrace_start`（三条题目、库元数据）、最多三条 `modeltrace_sample`、`modeltrace_complete`（整轮结果）。等待时发送 SSE 注释保活。前端只在收到最终完成事件后保存历史；停止、关闭弹窗或断连会取消当前上游请求并停止剩余题目。每题提供通用错误类别，不把可能回显凭据的上游错误正文写入测试历史；当前界面不采集上游 request ID 或 token 成本明细。

来源及固定版本见 [内置算法说明](../backend/internal/pkg/modeltrace/README.md)。无需新增配置或运行时依赖；回滚二进制不会修改数据库，浏览器记录可保留或手动清理。旧版界面不会读取新增的独立历史键。
