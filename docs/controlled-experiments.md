# 受控通道实验

管理后台入口：**智能运维 → 受控实验**，路径 `/admin/controlled-experiments`。只有完整管理员可以读取题库、查看报告和启动实验；观察员不能访问这组 API。

这是固定题库的实验执行与报告功能，直接使用 Sub2API 的现有转发代码。它检查所选账号通过指定通道提交请求时的配置、生成资格、协议完整性、答案得分、工具调用和用量记录。它不能独立证明第三方服务背后的物理模型身份，也不会把几道题的分数解释成模型的通用能力。

## 使用流程

1. 选择请求模型和推理强度，选择筛选题或确认题，也可以勾选部分题目。
2. 配置 1–4 条“账号 + 通道”。账号 ID、母号 ID、代理 ID和模型映射在保存时冻结。WS、Prism 和 BPS 必须已对该账号及模型启用；Prism/BPS 还受现有协议总开关约束。
3. 配置重复次数、提交预算和单次超时，保存草案。草案不生成答案，保存后的配置不可修改；需要变更配置时新建实验。
4. 查看冻结配置后点击“启动实验”。每条可用通道先做一次随机字符串资格探测；探测通过才执行题库。
5. 查看逐次记录中的实际通道、模型、推理强度证据、结束事件、身份稳定性、用量来源、评分与工具记录。可导出完整 JSON 报告。
6. 点击停止后，等待当前提交结束并保存其结果。后续题目及工具续轮不会继续提交。

选择“原生 WebSocket”不会自动开启账号 WS 配置。API Key 和 OAuth 账号各有对应的 WebSocket Mode；模式为 `off`、强制 HTTP、网关 WS/账号类型开关关闭或仅支持 HTTP bridge 时，运行前检查返回 `websocket_not_enabled` 并跳过整个通道，不占模型提交额度。先在账号编辑中配置实际支持的 WS v2 模式（如 `ctx_pool`），确认上游确实支持 Responses WebSocket，再新建实验。已跳过的通道不会在原实验中补跑。页面会显示“该通道未执行”及配置提示，HTTP 等其他可用通道仍可继续。

实验按题目与重复次数交替通道顺序，固定账号，串行提交。它沿用现有凭据、代理和模型规范化规则，关闭实验请求中的账号切换、协议降级和生成重试。普通业务流量仍可能影响时延和可靠性，因此实验结果应结合运行时间和正常流量解释。

## 题库与评分

题库源于用户提供的 Fenjue 的 `fenjue/research/tasks.py`，固定种子 `20261007`，版本 `fenjue-v1-20261007`。运行时使用嵌入的 JSON 数据，不依赖 Python 或额外的评分模型。原材料未附明确 LICENSE；题库来源和再分发授权状态应由维护者核实，本次没有补充或推断第三方授权。

| 类别 | 筛选题 | 确认题 | 评分依据 |
| --- | ---: | ---: | --- |
| SQL | 3 | 8 | 返回严格 JSON 中的 SQL；执行七套隐藏数据，对照隐藏的有序结果 |
| 约束推理 | 3 | 8 | 按隐藏答案严格比较 JSON 的结构、类型与值 |
| 长上下文 | 3 | 8 | 从包含干扰内容的合成记录中提取答案，严格比较 JSON |
| 工具续轮 | 3 | 8 | 答案正确，并有实际本地读取所有必需记录的调用证据 |
| 合计 | 12 | 32 | 总计 44 道固定题 |

隐藏答案、工具记录和 SQL 数据不进入初始模型请求。只有公开题目、指令、工具声明和必要续轮历史发送给上游。工具只读合成记录，不访问网络或生产数据。

JSON 评分拒绝重复键、额外 JSON 值、Markdown 围栏、超深嵌套及类型不一致。精确答案和工具题为 0/1 分；SQL 分数是通过的隐藏用例比例，七个用例全部通过才算题目通过。通道平均分按已评分的最终题目答案等权计算。

SQL 运行在独立内存 SQLite 中：只读、禁用可信 schema、限制函数和语法、每个用例最多一秒，并限制编译资源、结果行数和输出字节。支持常用 SELECT、JOIN、窗口函数和非递归 CTE，包括显式 CTE 列名。写入、文件 I/O、扩展加载、数据库元数据访问、递归和多语句会被拒绝。评分中的 SQL 错误或资源限制算答案失败；传输错误或未完成的响应不作为答案零分。

工具续轮在内存中保留全部原始输出项，包括不透明的推理续轮信息。持久化报告只保存答案、诊断和安全的工具调用轨迹，不保存凭据或不透明推理状态。

## 预算与成本

- 每个实验最多 300 次提交预留、1–3 次重复；每次请求超时 30–720 秒。
- 每条通道的资格探测计一次；每次工具续轮也计一次。
- 数据库事务先预留，再向上游提交。失败、未发送、未知或进程中断的预留都不退款。
- 完整计划的上限 = 通道数 ×（1 次资格探测 + 重复次数 × 各题最大提交次数之和）。提前结束的工具题可能使用更少次数。
- 预算低于完整计划时，预算耗尽立即停止，已经完成的记录保留；未配对样本不会补题或重做。
- 美元金额按已记录用量和现有模型价格计算，倍率为 1；缓存读取/写入与普通输入拆为互斥计费桶，并沿用 BPS 的缓存写入计价设置。
- 这是实验独立账本中的用量计价金额，不是客户账单、实际采购价或美元硬上限。没有完整用量的响应以及未知结果都标记成本不完整。
- 当前 `production` 的 Prism 转发接口没有可信的上游 token 用量；实验标记用量不可用、成本不完整，不根据适配器回显伪造计价金额。

## 资格、协议与比较的解释

运行前检查记录账号状态、通道开关和模型目录。目录列出模型不等于账号拥有生成资格；目录查询失败也不会伪造资格。实际的随机回显生成探测通过后，才标记“生成已验证”。运行结束不代表每条通道都通过了探测。

逐次诊断区分：

| 证据 | 含义 |
| --- | --- |
| `actual_channel` | 在发送点实际通过的 HTTP、WS、Prism 或 BPS 路径 |
| `upstream_status` | 捕获的上游/适配器原始 HTTP 状态；没有证据时留空 |
| `forwarding_status` | 网关诊断状态；例如上游 200 后流中断产生的本地 502 |
| `upstream_model` | 最终送往转发路径的模型；包含现有规范化和映射结果 |
| `response_model` | 原生上游原始响应声明的模型，或适配器声明；不把客户端重写的模型名当原始证明 |
| `request_sent` | 从最终发送请求得到的推理强度，缺少上游独立声明 |
| `upstream_declared` | 原生 Responses 响应声明的推理强度 |
| `adapter_declared` | Prism/BPS 适配器返回的声明，可能来自请求回显 |
| `identity_stable` | 提交前后所选账号、母号身份、代理 ID和模型映射保持一致 |
| `unknown` | 请求可能已经执行，但未得到可确认结果；不会自动重放 |

严格配对比较只纳入：同一题、同一次重复、双方完成且已评分、账号与路由稳定、响应模型一致，且原生上游独立声明的推理强度一致。差值是右侧平均分减左侧平均分。适配器回显和缺少声明的样本只显示单独得分与记录，不进入严格配对比较。因此 Prism/BPS 当前可能没有可用严格配对样本。

报告同时显示完成提交数、协议失败、未知结果和评分覆盖。高分但覆盖少，或者失败样本多，不能解释成通道更好。未知结果、缺失结束事件、拒绝、冲突的模型/输出、工具参数不合法都有单独诊断。

## 中断与隔离

数据库行锁限制提交预算，部分唯一索引保证所有应用副本最多有一个活动实验。每次预留续约 15 分钟租约。进程退出、保存失败或租约过期后，实验标记中断，未解决预留标记未知；再次启动被拒绝，管理员须新建实验。没有定时自动实验或未知请求重放。

实验使用观察模式，不触发质量规则自动冷却、停用或调整账号。不会自动启用 WS/BPS/Prism，且每次提交前重新检查协议总开关。当前明确不支持插件、passthrough、Copilot SDK、PAT、Agent Identity 和 Chat Completions 转换路径；这些路径在探测前阻止。

## API

所有路径均以 `/api/v1/admin/controlled-experiments` 为前缀，复用现有管理员认证：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/catalog` | 公开题目及题库版本；不包含隐藏评分数据 |
| GET | `/` | 实验历史，`before_id` 游标，最多 30 条 |
| POST | `/` | 保存固定配置草案 |
| GET | `/{id}` | 配置、运行前检查、记录与统计报告 |
| POST | `/{id}/start` | 明确启动一次，拒绝重启或并行活动实验 |
| POST | `/{id}/stop` | 本次提交结束后停止，或者取消草案 |

## 验证与升级

验证包括全部 44 道标准答案、JSON 契约、SQL 隔离、工具证据、四种真实转发代码的模拟上游、单提交与禁止重试、真实隔离 PostgreSQL 的并发预算和中断恢复，以及前端类型、页面测试和生产构建。

完整 API 验证使用 `backend/testdata/controlled-experiments/fixture.go` 的合成上游和隔离 PostgreSQL/Redis，不调用真实模型。`scripts/verify-controlled-experiments.ps1` 仅允许 loopback 测试地址，检查草案不提交、两条通道的资格/工具/评分、预算停止和缺少结束事件。`bootstrap.sql` 是虚构管理员的测试状态，不能复制到生产。

本次增加迁移 `268_controlled_experiments.sql`，只新增实验和提交记录表。回退应用镜像时保留这些表即可，原业务表和迁移文件不需要删除。升级前保留旧镜像、配置、数据库备份和 Prism 未解决状态；生产验收只读取目录、入口和配置，不自动消耗模型额度。
