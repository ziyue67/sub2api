# Excel/BPS OAuth 刷新与 401 恢复

BPS 返回 401 时，独立 Excel OAuth 凭据中的 refresh token（RT）仍可能有效。应先保留 RT，由后续 token 获取触发刷新；当前模型请求仍返回错误，不自动重放。

## 与 Codex 刷新机制的关系

本仓库 Codex 的普通 401 处理位于 `ratelimit_service.go`：失效 token 缓存、临时停调，不用请求快照覆盖 credentials。统一 `OAuthRefreshAPI.RefreshIfNeeded` 在刷新前加锁重读，遇到 `invalid_grant` 时重读凭据以识别并发轮换。

Excel 采用相同的恢复约束，但不直接套用主 Codex 账号状态处理：

| 约束 | 独立 Excel grant 的实现 |
| --- | --- |
| 资源接口 401 不直接丢弃 RT | 仅标记对应 AT 被拒绝，保留加密 grant 中的 RT |
| 401 状态写入不能干扰 RT 轮换 | 401 标记与刷新共享本机锁、同一 Redis 锁键；401 拿不到锁就不改写 grant |
| 刷新使用最新凭据 | 获得锁后重新读取 grant，并再次检查到期时间/拒绝标记 |
| invalid_grant 不能直接归因为当前账号失效 | 重读数据库；凭据已被替换时，校验并使用有效的新 grant |
| 不暴露未保存或已被拒绝的 AT | CAS 未成功时只允许返回数据库中新 grant 的有效 AT；已标记或校验失败时返回错误 |
| 一个授权失败不误伤另一份授权 | Excel 使用独立存储及 `openai:excel:account:<id>` 锁，不修改主 Codex 凭据或停调状态 |

这是对本仓库实现的对照，不代表所有服务端 401 都具有相同语义。Codex 原生路径对 `token_revoked` 等错误的账号策略未修改；独立 Excel 路径继续通过刷新端点的 `invalid_grant` 判定 RT 是否需要重新授权。

## 请求流程

1. 正常 AT 尚未接近过期、也未被拒绝时，校验身份后直接使用，不获取刷新锁。
2. BPS 返回 401 时，非阻塞获取本机锁，再尝试 Redis 刷新锁。任一锁被持有，说明其他凭据操作正在执行，本次 401 不改写密文；Redis 出错同样不写入。原请求返回失败。
3. 获得两层锁后重读 grant。只对仍匹配该请求 AT 的 grant 写拒绝标记；旧 AT 的迟到 401 不影响已轮换的新凭据。
4. 后续请求发现到期或拒绝标记，走同一个刷新锁，锁内重读、调用 Excel client 对应的刷新端点，并 CAS 保存新凭据。成功保存后清除标记。没有重放原模型请求。
5. 刷新期间到达的 401 因锁被持有而跳过写入，不能改变正在刷新请求的 CAS 快照。刷新失败时，原有到期条件或拒绝标记保留，后续仍可再次尝试。
6. `invalid_grant` 时先重读；若已有替换的 grant，校验身份、AT 有效期和拒绝标记。只有原 grant 未被替换时才条件删除；删除后再次检查是否并发写入新 grant，避免错误提示重新授权。删除/重读异常返回错误，不当作重新授权已确定。
7. 刷新成功但 CAS 因另一次授权替换而未命中，同样只使用数据库中的新 grant，不覆盖它，也不返回本次未保存的 AT。

## 与凭据诊断的整合

401 保留 RT 时，通过既有 CAS 事务把诊断记录为 `auth_failed`，表示当前 AT 被拒绝；不能仅凭资源端的 `token_revoked` 就把整个 grant 判定为不可续期。刷新成功在同一凭据保存事务中更新 `not_expired`。刷新期间跳过的 401 不改诊断，避免覆盖已成功刷新后的状态。主账号状态与人工停调标记不改变。

## 并发边界与兼容性

刷新锁租期沿用 60 秒；持锁后的读取与上游调用使用 50 秒上下文预算，上游调用另有 45 秒上限，为脱离请求取消的 5 秒保存和 2 秒释放预留时间。401 路径不等待本机锁，不触发 OAuth 网络调用。生产 Redis 锁与主 Codex 锁隔离；不配置 token cache 的嵌入场景只有本机保护，不可据此宣称多进程安全。

拒绝标记保存在现有加密 JSON 内，不新增 schema、配置或 API。旧 grant 没有标记，仍按原到期逻辑使用。旧二进制忽略标记并可能恢复 401 删除行为；新方案不能保护仍运行旧 401 实现的副本，部署需统一更新。上游刷新已成功但数据库不可用的恢复，以及 Redis 租约异常失效/进程长时间暂停，仍属于现有持久化和分布式锁边界，本改动不承诺消除这些故障。

## 离线回归

从仓库 `backend/` 执行：

```bash
GOMAXPROCS=2 go test -race ./internal/service -run '^TestExcel' -count=1
```

`openai_excel_oauth_recovery_test.go` 覆盖刷新中收到 401、新 RT 保存不受干扰、invalid_grant 与新授权替换交错、刷新成功但 CAS 遇到新授权、拒绝标记不被绕过，以及 Redis 锁占用/异常时不写凭据。跨副本锁占用使用 mock cache 验证键及不写入行为，没有用真实多进程 Redis 故障注入替代证明。

测试使用虚构凭据，不需要真实账号。历史 RT 已被旧实现删除时，本改动不能恢复该 RT；具体生产账号恢复仍需单独验收。
