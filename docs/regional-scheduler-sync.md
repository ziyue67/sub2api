# 区域调度业务同步接线（PR 3b）

基于 #419/#420/#421，新增真实 service.Account 与 SchedulerBucket 的完整文档、发布适配器、本地读适配器和后台拉取循环。没有注册生产 HTTP 路由、环境开关或 Wire 实例。管理员必须等鉴权、额度和账号状态路径区域化后才开放生产流量。

## 数据路径

1. 主站调用 `SchedulerSnapshotService.PublishRegionalScheduler`，传入可信配置里的桶列表和区域专属账号 ID。先通过已有仓库查询导出候选，不经过 Redis 或本地读取器。禁用分组输出空桶；未分配给区域、当前不可调度的账号不导出。
2. `RegionalSchedulerValidator` 校验文档版本、桶模式、重复桶/账号、账号平台、分组成员及区域账号白名单。首版不支持影子账号（需要母账号凭证所有权），遇到时拒绝整份文档。
3. `Replica.PublishNext` 从已持久版本下限递增，完整导出成功后才发布；发布失败不延长旧快照。过期版本仍参与递增。单文件只允许一个生产者进程，不支持多副本同时写。
4. 区域调用 `RunRegionalSchedulerSync`，立即尝试拉取，成功后按 interval，失败指数退避到 maxBackoff；取消停止循环。失败不会清空尚有效的旧视图，旧视图到期后自动拒绝。interval 至少 1 秒，最大退避至多一小时；实际值必须小于业务容许的同步延迟，建议远小于快照寿命。
5. 在请求启动前将 `NewRegionalSchedulerReader(replica)` 注入 #420 的 `SetLocalSnapshotReader`。读适配器取整个 Replica 原子视图，缺失桶为权威空结果，不回源；同一请求不会看到逐桶更新到一半的状态。每次读重新检查 Account.IsSchedulable，避免账号时间条件在同步后失效仍被选中。
6. 重启以 bootstrap=false 打开同一密文状态文件并注入 reader。过期/缺失/损坏不提供候选。正常重启不得自动清空或 bootstrap 绕过版本下限。

## 重要限制

- 这里是调度数据的业务适配，**不是完整 PR 3 的用户/API Key 同步**。用户、Key、权限和鉴权消费者仍需 PR 4 接入；订阅、余额和区域额度仍需 PR 5。原计划中的增量发布尚未实现，目前为全量替换。
- 仓库查询按桶顺序调用，默认 repo 不保证跨桶数据库事务快照。调用者需要提供一致读作用域或发布期间的配置变更协调；本 PR 不声称跨桶数据库事务一致。同一个 service 实例的导出加发布已串行化，避免慢的旧导出晚发布；不同实例/进程仍须由单一发布所有者协调。
- 区域账号白名单是可信部署策略，不是已经持久化的全局所有权系统。两个区域配置重叠无法由单节点检测；正式上线前必须具备账号独占/迁移排空协议。发布端和接收端都需配置同一归属策略。
- GroupID=0 沿用原仓库 simple/standard 查询语义，不新增跨租户权限。非零 group 必须有 GroupIDs 成员关系。任意自定义 platform 必须与账号平台匹配；混合桶仅 Anthropic/Gemini 与已启用混合调度的 Antigravity。
- 完整 Account 包含凭据和代理等敏感字段，仅经 #421 加密状态和受认证 HTTPS 传输；不生成日志或普通明文磁盘文件。字段白名单与只导出最小调度 projection 仍需收敛；当前并非可公开 API。
- 读取解码整份文档，存在 O(全量账号) CPU 和内存开销；尚未完成规模压测与索引优化，不能据此声称生产延迟改善。
- 后台循环当前无内置指标/日志；调用者应增加不含 payload 的同步延迟、版本及失败计数观测。主站定时发布与受认证 handler 的路由注册在部署接入时完成，当前只提供可调用接口。
- 凭证补全 GetAccount/GetAccounts、分组查询、限流/冷却写入、OAuth 刷新和账本仍是原路径。禁止单独启用本地候选就声称请求不再跨区。

## 验证

测试使用 mock AccountRepository、临时文件、虚构账号和 HTTPS httptest，不接生产数据库。覆盖授权区域过滤、导出失败保留旧版本/到期时间、禁用/删除同步、本地读取不回源、重启恢复删除结果、错误平台/版本/重复账号及取消。数据库事务、运行时路由、真实密钥轮换和模型延迟不在当前测试范围。
