# 自动配置

入口：**智能运维 → 自动配置**（管理员）。包含 BPS 默认配置、模型计价、OAuth 首次配置和并发升级；各功能独立控制。

## Excel / BPS 默认配置

此卡片只管理可复用的默认模板。账号编辑和批量编辑中的 BPS 协议提供两个互斥开关：

- **使用默认配置开启**：打开开关时填入这里保存的模型和选项，填入后仍可单独调整。
- **使用初始配置开启**：打开开关时恢复原始表单：三个初始模型候选，所有附加功能不勾选，再自行配置。不读取默认模板。

两种方式只在手动操作开关时填入当前表单。切换方式会重新填入相应的模型和选项；关闭当前开启的开关即关闭 BPS，保存账号后才生效。**新建、导入和同步账号不会因为默认模板而自动启用 BPS**，此功能没有账号初始化开关。

推荐模板选中 gpt-6-astra、gpt-5.6-sol、gpt-5.6-terra，以及“忽略历史中的加密消息内容”“遇到 BPS 403 错误时自动关闭协议”“创建缓存按普通输入计费”。其他选项默认关闭。模型和选项均可修改；工具、图片、403 恢复、调组及会话代理收在“更多选项”中。

“恢复推荐选项”恢复模板中的模型和勾选项。账号内的“管理默认配置”链接打开此页面；保存模板不会覆盖任何账号。编辑已有账号只回填账号自己的设置；模板读取失败保留当前模式和选项，关闭弹窗或切换账号会丢弃旧请求结果。观察员保留初始配置和手动编辑能力，不读取管理员模板。

默认模板复用 settings 中自动配置对象的 excel_bps 字段，无数据库迁移。账号保存 openai_excel_bps_config_mode 以便重新打开时显示所选方式；此字段只记录选项来源，不改变后端协议路由。旧账号没有此字段时显示为原有初始方式，并保留其已保存选项。

## 模型计价

为 Luna 等低价模型设置独立的用户收费倍率。默认预填一条规则：`gpt-6-luna*`、**10×**；新增规则也默认 10×。可逐条调整倍率（1–1000，支持小数）、添加其他模型或删除规则。开关默认关闭，启用并保存后，对所有账号的新 token 计费生效，与 OAuth 首次配置和并发升级独立。

- 根据实际用于定价的模型匹配，包括模型映射、无价模型回退和获准采用的响应模型；不按客户端名称随意推断“低价”。
- 支持完整模型名称或末尾 `*` 前缀通配，忽略首尾空格和大小写。精确名称优先，再取最长前缀；一次请求只应用一条规则。未匹配维持 1×。
- 只增加用户的 token 实际扣费，包括输入、输出与缓存 token；叠加现有用户/分组、账号用户收费和高峰倍率。例如分组 0.2×、模型 10×，其余倍率为 1 时，最终为基础 token 价格的 2×。免费分组（0×）仍免费。
- 余额扣费、订阅用量、API Key 配额使用同一调整后金额；用量日志的收费倍率包含模型倍率。模型基础价格、原始费用、账号成本倍率及上游成本统计不变。图片/视频/语音按次费用、渠道按次计费和搜索附加费不应用此倍率。
- 响应模型若加上模型倍率后会提高实际费用，则不采纳该响应模型，继续按原定价模型收费。Free Fast 仍按标准档 token 价格乘本模型倍率收费，不重复加倍。
- 配置复用 settings 中的 `model_billing` 字段，无数据库迁移。旧配置默认关闭；旧客户端保存未包含该字段时保留当前规则。保存的配置快照会显示模型规则。
- 配置缓存最多约 15 秒刷新一次；单次结算使用同一个快照。刷新失败保留上一份有效策略；服务刚启动且首次读取失败时暂不加倍，并记录警告。关闭并保存后，后续结算恢复原倍率，历史账单不追溯修改。

## OAuth 账户首次配置

选择一个 OAuth 平台，设置优先级、负载因子、初始并发和目标分组。新账号首次创建时使用这四项模板值，覆盖导入请求携带的相应值；名称、代理和计费倍率继续沿用创建请求；模型映射补充缺失规则并覆盖同名直通项，其他凭据不变。优先级越小越优先，负载因子只影响调度负载计算，与实际并发上限独立。

覆盖管理员创建 API、OAuth 授权创建、批量账号导入和 CRS 新账号同步。重新授权、凭据刷新、更新已有账号和 API Key 类型不会触发首次配置。模板中的分组必须启用且属于所选平台，保存和实际创建时都会校验。

首期保存一套平台模板；更换平台时重新选择分组。首次配置不会追溯批量修改存量账号。

### 模型映射

模型映射位于“OAuth 账户首次配置”内部，共用现有的启用开关和 OAuth 平台选择。启用首次配置并保存后，新 OAuth 账号首次创建时会把规则写入 credentials.model_mapping：补充缺失的源模型，并覆盖源模型与目标模型相同的直通项（例如 gpt-5.4 → gpt-5.4）。已有的非直通自定义映射优先，其他映射及凭据保留。

OpenAI 预填 **gpt-5.4 → gpt-5.5**，可修改、增删规则，删除全部规则表示不自动添加映射。最多配置 100 条，请求模型不能重复，可在末尾使用 *，目标模型必须是具体名称。切换平台时清除原平台规则，OpenAI 使用上述示例，其他平台从空规则开始。

旧版配置没有 model_mappings 字段时，后台继续沿用原有路由；管理页面为 OpenAI 预填示例，保存后才将映射应用于后续新账号。已保存的空规则保持为空，不会恢复示例。已有账号、重新授权、凭据刷新、CRS 已有账号更新和 API Key 类型不应用模板。

OpenAI OAuth 新账号原本没有显式映射时，自动添加别名同时写入 credentials.model_mapping_mode=aliases，保留原本的默认模型准入范围。命中规则仍按目标模型转发；未命中时沿用默认准入，保留其他厂商模型的默认过滤。导入时已有非空模型映射，或明确指定 whitelist 模式时，继续保留其白名单语义，不自动扩宽。

未标明模式的存量账号继续使用原有白名单语义：非空 model_mapping 只允许映射中的请求模型或通配符命中的模型。仅凭自动配置历史标记无法区分原始白名单意图，因此不会自动改写。确认账号应服务默认模型后，可在账号编辑开启“模型映射仅作为别名，保留默认模型范围”，或批量编辑勾选“修改所选 OAuth 账号的模型映射范围”。批量操作只写模式，保留每个账号原来的映射及凭据，不自动开启 BPS；关闭别名模式即恢复白名单。

别名模式参与调度轻量缓存、模型目录和最终模型检查，不绕过分组模型限制。旧客户端批量修改 model_mapping 而不指定模式时，对已有别名模式账号恢复 whitelist，避免意外忽略新白名单；仅更新其他字段不触碰模式。重新授权和凭据刷新保留映射模式。该字段无需数据库迁移；多实例环境先升级所有参与调度和缓存发布的实例（包括网关与控制面），再切换存量账号模式，避免新旧实例的准入行为不同。旧二进制不认识 aliases，回滚后非空映射会恢复白名单行为，存量账号应重新核对模型范围。

## 账号并发升级

选择允许升级的账号分组后启用。此范围包括选中分组内的新旧账号，不限于 OAuth。以下参数均可修改：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 每档连续成功次数 | 20 | 在当前并发档位累计的成功请求数 |
| 每次提升并发 | 1 | 满足成功次数后增加的并发数 |
| 最高并发 | 100 | 自动升级的上限，已高于上限的账号不会被降低 |
| 失败 / 升档后冷却 | 60 秒 | 冷却期间不累计成功次数 |

观察 HTTP 文本生成入口：Responses、Chat Completions、Messages、Gemini generateContent / streamGenerateContent。只有完整结束的成功响应计入升档；流式错误和缺少完成事件的断流不会按 HTTP 200 计成功。客户端取消不加成功计数。Count tokens、后台探测、图片/视频任务和 WebSocket 会话不属于首期统计范围。

失败会清零本档成功次数并冷却，不自动降档。故障转移时，失败账号清零，最终成功账号可计一次成功；同一请求在同一账号发生失败后再成功，按失败处理，避免重试掩盖不稳定情况。影子账号、无限并发账号，以及当前不可调度账号不自动升档。

升档只调整并发数，不调整优先级、负载因子或分组。开启自动并发升级时，账号列表显示当前档位、上限、已累计次数和下一档，进度条使用浅灰底和绿色填充。关闭后，整块升级进度 UI 隐藏，历史进度仍保留在账号数据中。开关状态随账号列表加载、手动刷新和自动刷新更新；未能读取开关状态时不显示。

## 生效、存储与回滚

- 配置保存在 settings，进度保存在 accounts.extra 的独立字段；没有新增数据库迁移。
- 保存会生成新的规则版本，并从保存后开始的请求重新计数；其他实例最多约 15 秒刷新一次配置。
- 请求结束只投递有界队列，不等待数据库或发邮件。进度与并发修改在同一数据库事务中完成，通过账号行锁避免多实例重复升档；升档同时产生调度缓存失效事件。
- 队列溢出或存储失败会暂停本实例的升档，配置页面显示暂停提示。排除异常后重新保存配置恢复。服务重启后，各账号从下一条结果重新开始成功计数；已提升的并发数保留。
- 管理员手工修改并发后开始新一轮观察；旧请求不会把并发改回旧值。关闭开关停止后续自动处理，已经写入的账号配置与并发不会自动还原。
- 二进制回退可忽略新增配置和进度字段；如需回退已经提升的并发，请在账号管理中手动修改。

## 长回复的成功计数

OpenAI 原生、OAuth、透传和 Excel/BPS 的流式响应，在网关确认成功结束且完成转发后提供账号级完成标记。并发升级统计使用该标记，不再因结束事件超过错误日志的 16 KiB 采样上限而将完整回复误判为失败。错误日志采样上限保持不变，也不会为统计额外保存完整响应。

失败尝试、流内错误、HTTP 错误及客户端取消仍按原有规则处理；标记与账号 ID 绑定，不会给切换后的其他账号补记成功。已有计数、冷却和升档阈值不变，修复只影响之后完成的请求，不补算历史请求。
