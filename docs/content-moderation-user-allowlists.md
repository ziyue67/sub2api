# 内容审查用户白名单

管理员可在用户编辑页的“内容审查用户管理”中分别设置四个开关，也可从安全审计用户名单编辑。保存需要操作原因、确认以及当前版本；服务端返回保存后的实际状态，缓存失效失败会报错，需重新加载核对。保存白名单不会解封或清零，撤销同样不会改用户状态或计数。

| 开关 | 作用 |
| --- | --- |
| 自动封号白名单 `auto_ban_exempt` | 仍审核、仍拦截当次风险、仍计数，并按独立邮件开关通知，只免除该机制的自动封号 |
| 关键词拦截白名单 `keyword_exempt` | 仅跳过前置拦截模式中的关键词层，不改变原本没有关键词检查的后台观察路径 |
| 外部审核 API 白名单 `api_audit_exempt` | 跳过外部内容审核接口，不发送该审核请求；关键词按原策略继续生效。当前 TypeSafe AI 引擎仅审文字 |
| 邮件通知白名单 `email_exempt` | 仅停止该用户内容审查的违规提醒、审查自动封号及 `cyber_policy` 通知邮件；仍审查、拦截、计数、记录历史与执行处罚。不影响验证码、安全登录、余额等其他邮件 |

四个开关独立组合；新开关默认关闭。旧自动封号白名单不会自动获得新豁免。

前置拦截模式：

| 审计策略 | 无审查豁免 | 仅关键词豁免 | 仅 API 豁免 | 两类审查均豁免 |
| --- | --- | --- | --- | --- |
| 关键词 + API | 命中词即拦；否则调用 API | 调用 API | 命中词即拦；否则放行 | 跳过这两层 |
| 仅关键词 | 命中词即拦；否则放行 | 放行 | 命中词即拦；否则放行 | 跳过这两层 |
| 仅 API | 调用 API | 调用 API | 不调用 API | 跳过这两层 |

后台观察模式原本不执行关键词层，关键词豁免不会改变该路径；API 豁免会阻止入队，已排队任务在发送前重新读取豁免，尊重新授予的 API 豁免。已经开始的外部请求无法撤回。撤销豁免后下一次请求按当前状态审核；版本围栏继续阻止旧异步结果触发过期账号变更。

这些开关不豁免模型服务商明确的 `cyber_policy` 拒绝、终止或止发，不允许因此重试；也不豁免认证、余额、配额、IP 安全及其他独立硬门槛。已有哈希风险拦截按原路径保留。

用户名单展示具体豁免类型，并支持各类型筛选；“白名单”匹配任一开关，“非白名单”匹配四个开关均关闭的已管理用户。原 `exempt` / `enforced` 查询参数按此解释；精确筛选旧自动封号类型使用 `auto_ban_exempt`。列表不包含对话正文或凭据。

迁移 `298_content_moderation_exemption_types.sql` 只给审核状态表与操作审计表添加默认 false 的字段，保留旧数据与账号状态。不需要 Ent/Wire 生成。迁移为 forward-only，回退二进制不会删除字段；回退后的旧版本不识别新增豁免，需评估恢复审核的影响。

邮件通知白名单在三条真实通知入口生效。管理保存任何白名单字段（包括仅修改邮件开关）都会递增同一用户状态的 `version`，保留原有全局版本围栏：保存前捕获旧版本的后台观察或异步记录任务，即使仍继续审查、保留风险日志，也会因版本不匹配被拒绝写入命中计数、执行账号处罚和发送通知。仅修改邮件字段不保证旧排队任务的计数或处罚仍生效，也不会为这些任务绕过版本比较。

保存后捕获当前版本的新任务仍按原规则计次和处罚；开启邮件白名单只抑制其中的审查邮件。撤销同样递增版本，不解封、不清零；之后的新版本任务按原条件恢复通知，仍受认证、账号状态等门槛限制。已被禁用用户需要单独按来源解除禁用后才能发起新的已认证请求。已跳过的通知不会补发，历史 `email_sent`、阈值快照及封号证据不按现在状态重算。

对具备通知资格的任务，邮件入口直接读取用户最新状态，不使用排队时或认证缓存里的值。模板路径在渲染后、内置正文及模板回退路径在调用 `EmailService.SendEmail` 前复查；读取失败时本次不发邮件并记录错误，不通过回退绕过。这个边界不与 SMTP `DATA` 或管理保存构成原子操作：进入 `SendEmail` 后仍有 SMTP 配置读取和网络发送，之后的管理保存无法保证撤回已开始的发送。

邮件豁免不覆盖全局配置：`email_on_hit` 仍决定是否触发违规提醒，审查封号和 `cyber_policy` 通知保留原有独立触发条件。它不跳过上游 `cyber_policy` 拒绝或止发，也不授权重试。

迁移 `301_content_moderation_email_exemption.sql` 仅给审核状态表和管理操作审计表增加 `email_exempt BOOLEAN NOT NULL DEFAULT FALSE`，不改旧迁移；旧记录默认 false，历史操作不继承当前值。管理 API `exemption` 操作中省略该字段（包括旧客户端只发送原三类字段）保留当前邮件设置，显式 false 才撤销。保存仍要求管理员权限、1–500 字原因、确认、当前版本、缓存失效及服务端读回；新操作记录四个最终值。回退旧二进制会忽略邮件豁免并恢复原通知行为，数据库字段仍保留。
