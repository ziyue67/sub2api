# 持票时间统计

> PR 截图已从当前源码中清理，以减小源码包体积。[查看固定提交中的历史截图](https://github.com/ranxi2001/sub2api/tree/297e9201a2f6d6fe70073b370a5b71f49579accf/docs/screenshots/harvest-ticket-coverage)；下列文件名与验证说明保留用于追溯。

入口：管理后台 → 打票全流程。顶部新增账号平均持票占比，账号卡新增单账号持票占比、有票 / 无票时长和统计起点。

- 单账号比例 = 有票秒数 /（有票秒数 + 无票秒数）。15min / 60min 对应 20%。
- 整体比例 = 各参与账号比例的算术平均；整体时长分别为参与账号有票和无票时长的算术平均。账号统计起点不同，因此整体比例不一定等于两项平均时长之比。
- 后台每 5 秒采样，页面关闭仍运行；仅统计当前采集范围内满足采集账号策略且支持启用模型的账号。任一启用模型有有效门票即计有票，多模型不重复累计。沿用主票/备用票、身份、有效期与验收状态检查；Cookie 存在不代表持票。
- 采用前一次采样状态估算区间，已知过期点截断有票时长。采样之间新票、失效等变化最多存在一个采样区间的识别延迟，不宣称事件级精确统计。
- 仅统计当前进程观测时长，无数据库迁移或历史回填。重启、模型/范围/传输/目标长度及打票开关变化后重置。账号离开范围、失去采集资格后删除其统计，重新进入从零开始；新账号有至少两个成功样本后才参与平均。
- 查询失败及超过 15 秒的采样空档不计时；前端超过 15 秒未更新显示延迟。只有后台任务实例采样，独立 gateway 实例没有跨节点聚合，部署拆分模式时不能据此当作全局历史。
- 每 5 秒增加一次账号列表只读查询和 O(账号×启用模型) 内存检查；无额外上游探测、调度修改、票据写入或模型费用。只在内存保留账号 ID、期限及累计时长。
