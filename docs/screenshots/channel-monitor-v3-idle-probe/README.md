# 渠道监控 V3：空闲时主动探测

截图来自本地演示环境：

- Docker 里的 PostgreSQL 18.1 / Redis 8.4，按本 PR 代码（基于 production `884948ed2`）构建的后端，前端开发服务器，以及无头 Chromium（CDP）。
- 一个只监听本机的假 OpenAI Responses 上游，按账号的上游 key 决定立即回答、12 秒后回答，或一直返回 503。
- 分组、账号、用户全部是虚构的，没有连接生产库，也没有请求真实上游。

截图时间为 2026-10-11 20:10 前后（北京时间）。

## 演示设置

- 为了快点看到效果，页面设成 1 分钟一格、30 格（半小时），可用率范围 24 小时，每格最少请求数 1。探测器每分钟第 30 秒醒一次，所以每格都在结束前 30 秒判断。
- 6 个 OpenAI 分组，每个配一个指向假上游的 API Key 账号，每个分组一个 V3 组件：

| 组件 | 情况 | 空闲探测 |
| --- | --- | --- |
| Codex - 主力 | 每 15 秒有一个真实请求（经本机网关，正常记账） | 勾选 |
| Codex - 偶尔有人用 | 每 4 分钟一个真实请求 | 勾选 |
| Codex - 夜间 | 没有流量，上游正常 | 勾选 |
| Codex - 慢速 | 没有流量，上游 12 秒后才回答 | 勾选 |
| Codex - 故障 | 没有流量，上游一直返回 503 | 勾选 |
| Codex - 未开探测 | 没有流量 | 不勾选 |

- 探测模型都是 gpt-5.5，思考强度 low。演示从 19:34 开始，截图时每个格子都已有数据。

V3 原来就有，探测默认关闭，关闭时页面和原来完全一样，所以没有另拍「修改前」。「Codex - 未开探测」这一行就是没开探测时的样子。

## 验收要点

- 有真实请求的分组没有被探测：「主力」每分钟都有请求，探测表里没有它的记录。
- 「偶尔有人用」有请求的那一分钟看真实请求，其余分钟由探测补上，整条都有颜色。
- 没人用的三个分组每分钟各探测一次：「夜间」绿色，「慢速」黄色，「故障」红色。
- 「故障」连续 10 分钟以上红色，记为一条进行中的事件。
- 普通用户的提示框只显示「自动探测」、探测耗时和错误类型，看不到探测次数和原始报错。
- 1440 和 390 宽度下，`document.documentElement.scrollWidth` 都等于视口宽度，没有横向溢出。
