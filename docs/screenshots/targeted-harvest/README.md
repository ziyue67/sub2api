# 定向打票预算与并行通道

入口：管理后台 `/admin/harvest-flow` →「单号定向打票」。

本目录为实际 `HarvestManualConsole.vue` 的 Chromium 本地组件预览截图，使用虚构账号 `#42 · demo-account`，采集接口为 mock。修改前组件与中文文案取自 production `17d8c566264b0c60f1bd00f48c62fd6d08756f88`；修改后组件对应本目录所在提交的源码。截图不代表整页导航、真实出票或生产验收。

- `before.png`：原来的 100 次 / 32 路输入边界。
- `after.png`：填写 3,000 次 / 128 路，两项输入均无固定 `max`，浏览器有效性检查通过。
- `running.png`：点击「并行获取凭证」后，mock 收到 3,000 次共享预算与 128 路参数；显示运行状态和停止按钮。另已点击停止，验证 mock 请求取消并恢复开始按钮。

次数默认仍为 20，前端并行通道默认仍为 10。串行和并行都允许填写大于 100 的正整数预算，并行允许大于 32 路。实际准备的通道数取请求通道、总尝试预算和当前可用节点数的最小值；不会为用不到的通道分配监听端口。

并行采集每轮对可用节点遍历一次，跨任务从上次分配节点的下一个位置开始。游标保存在托管 Mihomo 的本地设置中，服务重启后继续；所有账号共享该采集游标。用完整个节点池后才绕回列表开头。国家排除、禁用和一次性节点保留原规则；若订阅更新删除了游标节点，则从更新后的列表开头重新开始。

超过常驻通道数量时会为任务分配临时本机监听端口，结束、取消或准备失败后恢复常驻配置。高并发仍依赖主机端口、文件描述符和内存等实际资源；资源分配失败会返回错误，不会静默退回业务轮询。一次性节点仍在发请求前标记已使用，游标也在发请求前持久化，因此取消或选择器失败可能跳过已分配但尚未完成请求的节点。

该修改不改变票体、路由 Cookie 或目标网关验收。`route_gateway_mismatch` 仍按原规则拒绝入库。
