# 共享账号池与区域并发租约（开发中）

美国节点与主站共享同一批上游账号，不迁移账号，也不改变主站面板。区域在后台领取一部分账号、用户和 API Key 的并发容量，请求在本地使用已持久租约；统一后台负责 OAuth 刷新和凭证/状态同步。此处仅实现并发账本事务核心，已有未启用的 ConcurrencyCache 适配器，尚未接入运行启动、后台 broker 调度或模型 handler，入口仍关闭。

## 全局容量

`slots.Primary` 让主站请求和区域 grant 锁同一份资源预算。`primary_used + granted` 不得新增至超过当时权威配置；限额从同一事务中的账号、用户、Key 读取，客户端不能提升总限额。例：账号总并发 4，租给美国 2，则主站最多新增 2，美国最多新增 2。同账号凭证和分组仍可同时存在两地。

非正数的无限维度不需要分配有限槽位；具体服务适配器须保持现有无限/禁用语义，不能把缺失配置当作无限。

**现有主站 Redis-only 并发实现不认识租出份额。必须先让所有主站实例的普通请求、API Key 排队、Live/WS 转换路径遵守新预算，才可以发放区域 grant。不能只在美国加本地限制。** 本 PR 还未提供这个运行开关，因此不会使正在运行的主站提前租出容量。

## 持久与排空

grant 有稳定 ID、区域、资源维度、槽位数、起止时间和单调 revision。续约只能保持身份和容量，增加版本及到期时间，不重复增加全局 granted。接收者拒绝旧版本和同版本不同内容。权威限额缩小到现有分配以下时拒绝继续续约；主站拒绝新增，区域旧 token 按原始到期时间停止新增。这是有界延迟配置收回，不是实时跨区全局撤销。

本地多个 Pod 使用同一 PostgreSQL，以租约行锁控制 used。重复相同 request ID 不加占用；已释放 ID不能复活。进程崩溃和 token 过期不释放已获得槽位；只有明确请求结束的释放才减占用。此策略优先避免超额，不能自动保证崩溃后的容量可用性，仍需结合持久请求账本和排空恢复工具。

主站先 `BeginDrain` 停止续约，区域 `Drain` 停止新增，等待 used=0 后 `Close` 提交区域、ID、revision 的关闭凭证；主站认证凭证并检查当前版本后才返还 granted。重复关闭不重复返还。单凭 TTL、网络断连或 Kubernetes 删除 Pod，不得回收区域容量。

## 未完成接线

- 适配器已支持普通账号/用户/Key 槽位；Key 采用即刻准入，满额返回既有 429；不暴露旧 Redis FIFO 或 Live transfer 接口，防止绕过租约。FIFO/Live 完整支持留待后续。现有 WS ingress 使用节点本地辅助缓存，turn 容量受普通槽位约束。
- 启动 provider 尚未绑定适配器；主站必须排空旧持有者、所有实例切换预算 authority 后才可发放区域 grant，不能混用旧 Redis acquisition。
- 后台 mTLS Handler/Client 已验证固定证书 pin、区域/用户/Key/账号范围及 grant 限额，提供 issue/renew/drain/close；还没有实际监听、分配/续约调度与美国本地 DB/缓存部署。
- 与额度预留、发送前授权复查、OAuth 后台刷新和账号冷却/RPM 的协调。
- 跨域共享账号的上游账额上限/平台额度处理，真实请求、断连、恢复和并发验收。
