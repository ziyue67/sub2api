# 请求惩罚与个人安全记录

请求惩罚独立于账号登录状态，默认关闭且处于观察模式。管理员在
「安全审计 → 提示词审计 → 请求惩罚策略」保存策略；模型与审核节点仍按各自原配置调用。
此策略同时接收现有内容审计（包含 TypeSafe / Jev）前置拦截，以及提示词审计
的明确 Block 结果。无需为了启用 Jev 命中计数而另外启动 Qwen3Guard。

## 策略

| 选项 | 未到阈值 | 达到阈值 |
| --- | --- | --- |
| 会话累计 | 拦截风险当次并记录 | 拒绝同一会话的后续模型请求 |
| 用户累计 | 拦截风险当次并记录 | 拒绝该用户所有 API Key 的模型请求 |
| 会话两级 | 拦截风险当次；该会话后续请求转受限分组 | 拒绝该会话后续模型请求 |

默认阈值 3 次、累计窗口 720 小时、处罚持续 24 小时；均可配置。
窗口是自首次命中开始的固定计数窗口；处罚到期或管理员解除后，新命中重新计数。
已生效的拒绝持续到处罚解除时间，即便计数窗口先结束。
切换策略使用独立计数命名空间，不把历史事件自动重算为新策略处罚。
观察模式仍存命中和计数，关闭观察后当前策略中尚未过期的处罚会开始执行。
关闭惩罚开关或风控总开关会停止新处罚检查与计数，但历史记录保留。

仅明确审核风险 Block 计数；超时、HTTP 错误、非法审核响应、Warn、
被已有处罚拒绝的普通请求都不增加违规次数。内容审计和提示词审计对同一请求
同时命中只记一次；WebSocket 每轮单独作为一次请求。异步审核的发现和处罚
在同一 lease-fenced 数据库事务中提交，重试不会重复计数。

配置适用分组控制新命中来源；已生效的用户处罚适用于该用户所有模型请求。
豁免用户、现有全局信任用户和管理员不执行自动处罚。
新策略接管适用请求后会关闭该请求对应旧内容审计的账号状态自动封禁，
避免将“限制模型请求”错误变成“禁止登录”；其他旧策略保持原行为。
历史上已被禁用的账号不会被本功能自动解封。

## 会话身份与路由边界

复用现有明确会话 ID 解析和 API Key 作用域的单向哈希；不使用 IP、User-Agent、
相似提示词、工具名或缓存亲和参数猜测会话。缺少明确会话标识时，仍记录当次
拦截原文，但会话策略不累计，也不会扩大为整个用户处罚。
下游共享一个 API Key 时，应为每个真实会话传递独立 session/thread ID。
更换明确会话标识意味着新的会话，不能当作不可绕过的终端用户身份验证。

受限目标必须与原分组平台一致，且已绑定到 API Key，并继续通过分组授权、
模型许可、订阅、余额和并发等现有检查。两级策略启用时，正常的多分组选择会排除
受限目标，避免绑定目标后正常会话因价格更低而被送入受限池。没有目标授权或目标不可用时明确拒绝，
不自动回退正常池，也不修改 API Key 的持久分组绑定。
路由后的正常请求仍走原有审核。命中当次永不因降级路由而放行。
审核范围继续采用路由前的源分组，避免目标分组未列入审核范围而停止后续累计。

WebSocket 后续轮省略身份时，可继承该连接前面明确解析的会话哈希。
已建立连接不会跨分组或跨账号中途切换；如果连接中途产生受限路由，下一轮
返回明确的重连错误。重连握手需带同一明确会话 ID 请求头，才能在分组准入前路由；
只有帧内身份而没有握手身份的客户端会被要求重连，不会绕过限制。

## 用户与管理员界面

- 「个人资料」展示当前限制、范围、原因、计数与解除时间。
- 用户侧边栏「安全记录」展示自己的历史命中，可按需展开对话提示词原文。
- 列表接口不返回完整原文；详情查询强制绑定登录用户 ID，不接受查询参数覆盖所有者。
- 管理员可查看记录、修改策略或填写原因解除某用户全部请求处罚；解除不删除历史。
- 原文按现有提示词提取器提取并限制最多 100,000 Unicode 字符，界面以文本显示，
  不执行 HTML；无法提取的非文本输入显示明确占位，不把原始请求 JSON 当作提示词保存。

请求惩罚不改用户状态，因此用户仍可登录、查看个人资料、历史与联系管理员。
用户级策略会影响共享该用户身份的下游；下游场景优先选会话策略。
