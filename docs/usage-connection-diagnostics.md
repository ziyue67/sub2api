# 使用记录：连接诊断

管理员在「使用记录」的「用量明细 / 错误请求 / 连接诊断 / 用户排行」切换到连接诊断。此页不向普通用户或观察者开放。

按共享的用户、密钥、账号、模型、分组及日期筛选，再按来源、观察结果、域名（可含端口）、IP 或请求/客户端/Trace ID 查找。日期窗口最多 31 天；每页 20 条，最大 500 页，不执行全量精确计数。跨越更长时间或超过分页上限时缩小筛选范围。

列表包含来源、时间、安全 URL、HTTP/TLS 协议、身份、模型、账号、观察结果、HTTP 状态、耗时及写出字节。详情展示应用事件时间线、出口尝试、断开/取消/写出错误和关联的结构化错误详情。HTTP 200 与记录的业务错误分别展示，不能把已开始 SSE 后的 502/503 当成请求成功。

## 数据来源和覆盖范围

- **应用**：现有 HTTP `POST .../responses` 与 `.../responses/compact` 的计时中间件在请求结束时独立写入元数据，包括未通过鉴权、没有用量/没有 token 的请求。记录不依赖计费成功，不重放模型请求。未覆盖其他应用协议、WebSocket turn、进程崩溃前尚未结束的请求。
- **历史记录**：查询已有 `request_timing_details`，以及没有关联明细的 Responses 错误记录。历史错误只提供已知业务结果和耗时，未采集的域名、物理 HTTP 状态、网络标记和事件时间线显示“未采集”，不伪造为 false 或成功。旧耗时记录缺少域名；按域名筛选不会匹配它。
- **Nginx/Caddy 入口**：由可选采集器独立上报，包含入口直接返回、后端不可达、客户端关闭等，即使没有到应用也可留存。部署接入见 [入口采集说明](../deploy/connection-diagnostics/README.md)。入口导入只允许管理员，不能上报或推断用户/密钥身份。
- **TLS**：解析已存在的 Caddy `http.stdlib` TLS handshake error JSON 日志时，保存来源 IP 与固定 `tls_error`，不保存原始错误消息。尚无 HTTP 请求，因此 URL、域名、用户身份、HTTP 状态和总耗时不能还原。

每个来源是一条独立观察，不能把入口条数 + 应用条数当成实际请求数或重连次数。入口若收到应用响应 `X-Request-ID`，可按它关联；入口无法连接应用时只有代理生成的 ID 或来源事件 ID。不会用 IP 把匿名记录强行归属某个用户。调查入口层时先清除身份/模型/分组筛选。

“应用侧完成”和“入口响应结束”均不等于用户收到/解析成功。DNS 失败、客户端到入口 TCP 建连失败，以及代理未写日志的 TLS 失败可能完全没有服务端记录；不能从空列表判断网络正常。需要同一时段的客户端日志或探测证据。服务端不能知道用户究竟改了多少行代码，也不能把每次界面“正在重新连接”与某条记录自动一一对应。

## 存储和运行边界

新增迁移 `294_request_connection_traces.sql`：独立表和时间/用户/密钥/域名/请求 ID 索引，没有修改用量计费字段、外键或重试策略。旧二进制不读写新表；回退保留该表即可，采集器导入应随回退停止。

元数据只保留服务端 ID、身份 ID、入口 host、路径路由词、协议、时间、状态、字节、UA 和受限计时结构；不记录正文、API Key、Cookie、Authorization、查询参数、任意路径能力令牌或原始网络错误。已存在的结构化错误通过原管理接口查看，不重复持久化错误正文。

应用写入队列容量 256，单快照上限 128 KiB，异步 SQL 最多重试 3 次、每次 3 秒，失败只影响诊断。队列溢出、最终写入失败和保留清理失败有汇总日志；并非无损审计。目标保留 30 天，每小时分批清理最多 10000 条；清理积压时需检查日志，不能声称超过期限立即删除。入口本地日志另按容量轮转。

列表数据库查询限时 8 秒。采集器导入最多 50 条/256 KiB，限时 5 秒，按事件 UUID 幂等确认数据库落库。采集器不在收到确认前推进游标；重试只重复诊断导入，绝不重放业务请求。

## 验收与验证状态

CI 应运行新增 middleware、handler、service、PostgreSQL 集成测试，前端 `UsageConnections.spec.ts` 和现有 UsageView tab/观察者权限测试，以及入口采集器离线单测。覆盖无用量失败、HTTP 200 + 失败终态、正常关闭不误判、匿名入口、查询边界、路径脱敏、幂等确认、轮转和失败游标保留。

当前最终改动未运行本地测试、前端类型检查/构建或真实页面截图；这些交给 CI。开发早期误启动的两次旧代码树后端检查均返回成功，但不能作为最终树验证。一次前端类型检查因无 vue-tsc 未启动；未安装依赖或为截图运行本地构建。CI 以 PR 对应提交为准；未合并、未部署。
